# staging 资源归属与隔离方案（2026-10-08）

> 触发问题：**预发布环境可以与正式环境共用 ACK / Redis / PostgreSQL 吗？**
>
> 一句话结论：**ACK 可以共用"非生产集群"，但不能与 prod 共用；Redis 不与 prod Tair 共用实例；PostgreSQL 不与 prod RDS 共用实例，且绝不共用同一个 database。** 落点选**雅加达（方案 A）**，不是马尼拉生产集群的 namespace。
>
> 本文件不新增裁定，只做一件事：把 `任务45环境隔离修订_2026-09-29.md` 的裁定**落到可 apply 的清单**，并**消解仓内现存的两处矛盾**（见 §2）。

---

## 1. 为什么不能与 prod 共用（本仓实测证据，非通用结论）

| 资源 | 共用会怎样 | 证据出处 |
|---|---|---|
| **ACK（马尼拉生产集群 `cd57e40ce9a634c1698c2f5c5e09bd93c`）** | Terway ENIIP 且 `pod_vswitch_ids=None` ⇒ **同集群任意 Pod 的源 IP 天然落在生产 RDS 白名单段内**；namespace 只是组织/RBAC 边界，不是网络边界 | `任务45:E1/E2/E3`（白名单 `10.0.16.0/20,10.0.32.0/20,10.0.48.0/20,10.0.64.0/20`；全集群 **0 条 NetworkPolicy**） |
| 同上 | 单节点池 `npaad418131aa84c899be022b5463d13bf`（4×g9ae.2xlarge）⇒ prod/staging 共享内核、kubelet、运行时、节点 ephemeral 存储；apiserver/etcd/Worker RAM 角色共享 | `任务45:E5`、`ack_ledger.md:4,57,61` |
| 同上 | **配额根本落不下**：马尼拉企业级按量 vCPU `total=64 / used=32`，prod 节点池 max=8×8C=64 ⇒ 峰值余量 **0** | `任务45:E6`、`Day2任务11_节点池付费方式裁定:66-69` |
| **Redis（Tair `r-5tsf1fe16543e274` / `tair-mnl-newapi`）** | 单实例、**DB 0、`default` 账号**、键名**无环境前缀**（`rateLimit:<uid>`、`<mark>+clientIP`、`<mark>:user:<id>`）⇒ staging 与 prod 撞同一个 key 空间，限流计数直接互相污染；内存淘汰是实例级的（`allkeys-lru`）⇒ staging 灌数据会淘汰 prod 键 | `Day1任务4_RDS_PostgreSQL §七`、`task7_tair.sh:173`、`middleware/rate-limit.go:128,224`、`middleware/model-rate-limit.go:88,102` |
| **PostgreSQL（`pgm-5tstdhko64x2c01w`）** | 同实例不同库只隔离了**数据**，没隔离**计算**：CPU/IO/`max_connections`/failover/小版本升级全共享；staging 的索引重建、锁风暴、参数调整、重启都会打到 prod。且该实例**公网 `43.118.96.65:5432` 已开启** | `任务45:E11/E13`、`Day1任务4_RDS_PostgreSQL` |
| 同上（数据面） | prod `new-api-master` 走 **GORM AutoMigrate**（36 表/177 索引），`common/init.go:89` 的 master 判断是 `!= "slave"` **字符串比较** ⇒ `NODE_TYPE` 留空即 master 即发 DDL。staging 一旦指向 prod 库，**启动就改生产 schema** | `Day2任务18`、`Day2任务23:67` |
| **ClickHouse 日志库** | 每次启动重放 3 条幂等 DDL，含 `ALTER TABLE logs MODIFY TTL`（由 `LOG_SQL_CLICKHOUSE_TTL_DAYS=90` 驱动）⇒ staging 接 prod CK 会**改生产日志表 TTL** | `model/main.go:395-407,468`、`任务45:F9`（dev/staging **不建 CK**） |

**结论**：这三类里，只有"计算面"存在可讨论空间，数据面（PG 库、Redis key 空间、CK 表）没有——共用它们不是省钱，是把预发布变成生产事故的直达通道。

## 3. 目标拓扑（方案 A 落地形态）

```
生产（不动）
  ap-southeast-6 马尼拉   ACK cd57e40…  ns new-api        ← RDS pgm-5tstdhko64x2c01w / db newapi
  ap-southeast-1 新加坡   ACK ca75829…  ns new-api(备)     ← 同实例同库（现状，无复制）
                          Tair r-5tsf1fe16543e274 (DB0)   ← 仅 prod 使用

非生产（本卡新建，全部 rg-nonprod rg-aek4hk3prqgqjcy）
  ap-southeast-5 雅加达   VPC vpc-newapi-jkt-dev 10.2.0.0/16
                          ACK cb0abf5bc06034f7bbdb991752f6f3e62（ack.standard，控制面免管理费）
                            ├ ns new-api-dev      （dev，已建集群但无工作负载）
                            ├ ns new-api-staging  ← 本卡交付
                            └ ns new-api-perf     （预留，本卡不建）
                          RDS pgm-d9j9p421lzx4gw73（pg.n2.2c.1m，单节点基础版）
                            ├ db newapi_dev
                            └ db newapi_staging  ← 本卡交付
                          Redis：集群内 redis:7 单副本 Service（不建 Tair）
                          日志库：staging 复用 PG（不建 CK，任务45:F9）
```

**共用关系的准确表述**：staging 与 **dev** 共用雅加达的 ACK 集群与 RDS 实例（namespace / database 级切分 + 本卡的 NetworkPolicy、ResourceQuota、独立账号）；staging 与 **prod** 是 **不同 region、不同 VPC、不同集群、不同 RDS 实例、不同 Redis、不同密钥** 五重分离。CEN=0、VPC peer=0 ⇒ 结构性不可达（`任务45:E12`），**不要为省流量费去建对等连接**。

## 5. 交付物与执行顺序

清单目录 `deploy/staging/`，沿用现仓执行通道 `deploy/ack_remote.sh`（RunCommand 载荷上限 24KB ⇒ 清单**必须分文件**，不要合并）。仓内 **无 `.tf`、无 Helm/ArgoCD**（grep 0 命中），故本卡交付**原生 YAML + aliyun CLI 脚本**，与 `manifests/`、`aliyun/ph/` 的既有口径一致；长期目标结构仍是 `git开发-发布-值班规范.md §7.3` 的 ops 仓库 `overlays/staging/`。

### 5.1 `manifests/10-namespace.yaml`
namespace `new-api-staging` + 标签（`env: staging`、`site: jkt`、`rg: rg-nonprod`）。标签是把计费/筛选维度留住的前提（`VPC与vSwitch落地:120`）。

### 5.2 `manifests/15-limitrange.yaml` + `manifests/20-resourcequota.yaml`
⚠ prod ns 有 Quota 但**无 LimitRange**（`Day2任务23`），staging 这里补上 LimitRange：否则 staging 容器忘写 requests 会被调度到独占整台 2C 节点，且 Quota 按 unlimited 口径吞掉。
Quota 口径按雅加达 2 台小规格节点算：`requests.cpu 3 / limits.cpu 6 / pods 20`（详见文件头注释的算法）。

### 5.3 `manifests/30-networkpolicy.yaml`
`new-api-staging` 内 **default-deny（ingress+egress）** + 白名单放行：同 ns Pod、kube-system DNS:53、集群内 Redis:6379、雅加达 RDS 私网 5432、上游 provider 443。
可行性已实测：terway-eniip 的 `policy` sidecar 在跑（`任务45:E4`）⇒ NetworkPolicy 生效，属可回退的软隔离（配错一条即失效，所以它是**第二道**，第一道是不同 VPC）。

### 5.4 `manifests/40-rbac.yaml`
SA `new-api-app`（**名字必须是这个**：ACR 免密拉取由 `managed-aliyun-acr-credential-helper` 只挂到该 SA，用 `default` 必 `ImagePullBackOff`，`Day2任务18` 坑 / `任务16` 坑 5）+ **namespaced** Role，无 ClusterRole 绑定。CI/CD 用的 kubeconfig/凭证必须是 namespace-scoped，禁止给 prod namespace 任何权限。

### 5.5 `manifests/50-redis.yaml`
集群内单副本 `redis:7` + `ClusterIP`，`--requirepass`，**不暴露公网**，禁用 `FLUSHALL/FLUSHDB/KEYS`（`task29_tair_sg.sh:22` 里那条仅存在于计划脚本，这里真正落地）。`REDIS_CONN_STRING` 指向 `redis://:<pw>@redis-staging.new-api-staging.svc:6379/0`——与 prod Tair 完全无关。

### 5.6 `manifests/60-deployment.yaml` + `61-service.yaml`
2 副本 `new-api-stable-rc`，`NODE_TYPE: "slave"` 显式写死（不留空、不靠 ConfigMap 继承）。
`MEMORY_CACHE_ENABLED: "false"`（`wf2/part2a.md:481`：多副本环境留 `true` ⇒ 余额随机跳变；仅**单副本** staging 允许）。
无公网 LB：`ClusterIP` + 内网访问（`预发与正式环境区别.md:126`）。

### 5.7 `task55_staging_pg_init.sh`
雅加达 RDS 上建 `newapi_staging` + 两个账号：`newapi_staging`（DML）/ `newapi_staging_migrate`（DDL，DBOwner），并把白名单**单独成组**只放雅加达 app/data vSwitch 段（`10.2.16.0/20,10.2.32.0/20,10.2.80.0/20` + data 段），**不复用** prod 的 `mnl_vpc` 组。

### 5.8 `ci_check_env_isolation.sh`
把 `任务45:380` 那条 CI 规则（"DSN 含 `pgm-5tstdhko64x2c01w` 且 ns≠`new-api` 即 fail"）实现为可跑的门禁，另加 4 条：prod Tair 串、prod CK 实例、staging 清单里 `NODE_TYPE` 缺失或为 master、staging 清单里 `MEMORY_CACHE_ENABLED=true` 且 replicas>1。与既有 `ci_check_migrate_versioned.sh` 同风格。

## 8. 红线（写进 CI 与值班手册）

1. staging 的任何连接串**不得**出现 `pgm-5tstdhko64x2c01w` / `r-5tsf1fe16543e274` / prod CK 实例（CI 硬门禁，§5.8）。
2. staging **不得**落在 `ap-southeast-6` 生产集群、**不得**使用 namespace `new-api`。
3. `SESSION_SECRET` 与 prod 不同值；密钥分环境独立生成、独立轮换。
4. 非生产侧禁止手工 `kubectl` 改 prod namespace；线上变更一律体现为 ops commit（`git开发-发布-值班规范.md §7.2`）。
5. staging 只做**只读**冒烟 + 自己的写；任何自动迁移/清理/补偿任务在 staging 执行前，先确认其 DSN 指向 `newapi_staging`。
6. 不为"省流量费"新建 CEN / VPC 对等连接（`任务45:§1`、E12/E16/E17）。
