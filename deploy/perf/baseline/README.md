# deploy/perf/baseline —— 基线归档与回归门禁

## 命名

`<YYYY-MM-DD>-<git short sha>.md`，例：`2026-10-30-1a2b3c4d.md`。
同一天多次运行用 `-run2` 后缀区分。

## 必填内容

1. **环境**：集群 / 命名空间 / 副本数 / 镜像 tag / mock 参数 / 节点规格。
2. **场景结果表**：每个场景的目标值、实测值、判定（PASS / FAIL / 未执行）。
3. **资源**：CPU 峰值（每 Pod）、内存峰值、`go_goroutines`（若有 Prometheus）。
4. **与上一基线对比**：同场景同口径的 rps / P95 / 内存变化百分比。

## 回归门禁

- 与上一基线相比，**同场景同口径**指标劣化 > 10% ⇒ 阻断发布。
- 跨口径（如 mock token 数变了）不得直接比较，必须在报告里显式声明口径差异。
- 只跑单次的结果不作为基线：需要同一档位连续两次、波动 < 5%。

## 已知口径坑

- `cpu_peak_sum` 来自 metrics-server 15s 采样，跨档不可精确比较，只看量级。
- 客户端分片数不足会把**客户端瓶颈**误判成服务端瓶颈：判定前先看 `dropped_iterations`。
- 开环与闭环的 RPS 不可混比：闭环 `RPS = VU ÷ 单次耗时`。
