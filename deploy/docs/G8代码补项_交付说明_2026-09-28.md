## 2. 设计取舍（评审时会被问到的点）

**2.1 `/readyz` 的三档定级**

```
主库   HARD    → 503：读不到计费库的 pod 必须摘出轮转
Redis  SOFT    → 200 + "degraded"：限流本来就 fail-open，这里杀掉 pod 等于把一次缓存抖动放大成全站故障
日志库 SOFT    → 200 + "degraded"：日志不在 SLA 证据链内，写失败降级为丢行
```

**2.2 限流降级不是"一律放行"**

- 普通 mark（GW/GA/DW/UP/SR…）→ **fail open**，直接 `c.Next()`；这部分流量在 ALB/WAF CC 防护层已有兜底。
- 认证关键 mark（`CT`、`UC:*`）→ 不退化成放行，而是**切换到 pod 本地内存固定窗口**（`RATE_LIMIT_CRITICAL_MEMORY_BACKSTOP`，默认 true）。暴力破解限制在缓存故障期间不能凭空消失；但也不能 fail-closed，否则缓存一挂所有人都登不进去，那是更坏的故障。
- 降级记忆的 key 与原 Redis key 同维度：用户维度限流降级后仍按用户计，不会退回按 IP（`middleware/rate-limit.go` `userRedisRateLimiter` 把 key 透传给 `degradeRateLimit`）。
- `RATE_LIMIT_FAIL_OPEN=false` / `RATE_LIMIT_CRITICAL_MEMORY_BACKSTOP=false` 可切回拒绝，但返回 **503 而不是 500**：这是依赖不可用，不是服务端 bug，客户端应当退避重试。

**2.3 邮件验证码限流（`EV`）本次未改**

`middleware/email-verification-rate-limit.go:25` 早已自带"Redis 出错→内存窗口"的兜底，与 §2.2 的口径一致，因此不重复改造，只在测试里把它的行为一起钉住。

**2.4 指标暴露面**

`/metrics` 不挂在应用端口上，而是 `net.Listen` 另起 9090 的独立 listener。理由：挂在业务端口上时，"别把它放出去"这件事只能靠 ALB Ingress 规则正确，一次误配就是把内部路由表和 QPS 挂到公网。现在即使 Ingress 写错，公网也拿不到。绑定失败只记日志不 fatal——遥测不能反过来把网关搞挂。

**2.5 中间件顺序**

`httpmetrics.Middleware()` 必须在 `gin.CustomRecovery` **外层**（`main.go:187-193`），否则 panic 请求在 recover 里写码前就返回，会被统计成 200。

## 3. 新增环境变量（全部向后兼容，默认值 = 现网行为）

| 变量 | 默认 | 取值 | 说明 |
|---|---|---|---|
| `RATE_LIMIT_FAIL_OPEN` | `true` | bool | 普通限流在 Redis 不可用时是否放行 |
| `RATE_LIMIT_CRITICAL_MEMORY_BACKSTOP` | `true` | bool | 认证关键限流是否启用本地内存窗口（false = 改 503 拒绝） |
| `METRICS_ENABLED` | `false` | bool | 总开关；关闭时中间件与 Observe* 全部 no-op，零开销 |
| `METRICS_PORT` | `9090` | int | 内部指标端口 |
| `METRICS_BIND_ADDR` | `0.0.0.0` | string | 集群内抓取需要 pod IP 可达 |
| `MIGRATE_MODE` | `auto` | `auto` \| `off` | `off` = 启动期不做任何 DDL，schema 归 golang-migrate |
| `READY_PROBE_TIMEOUT_MILLIS` | `1000` | int | 单个依赖探测超时 |

> ⚠️ `MIGRATE_MODE=off` **不能**在空库上启动：库必须先由迁移任务建好，否则 pod 会带着空 schema 起服务。灰度时先在存量库上验证。

## 7. Patch 之外仍要做的（不属于代码，不能算 G8 已完成）

集群侧脚手架已写在 **`deploy/aliyun/ph/g8-probe-manifests.yaml.tpl`**，但**未在任何集群上 apply 过**，落地前按该文件头部的前置核对逐项确认。剩余事项：

1. **K8s 探针声明**（该文件第 1 段，`kubectl patch --type=strategic`）：`/healthz:3000` liveness（`periodSeconds:10, failureThreshold:3`）、`/readyz:3000` readiness（`periodSeconds:5, timeoutSeconds:3, failureThreshold:3`）。`timeoutSeconds` 必须大于 `READY_PROBE_TIMEOUT_MILLIS`（默认 1000ms），否则探针自己先超时，等于把"依赖慢"误判成"pod 死"。
2. **ALB 后端健康检查**：路径改成 `/healthz`，别用 `/`（会命中前端路由并写访问日志）。
3. **NetworkPolicy**（第 2 段）：只放通监控命名空间到 pod `9090`。`METRICS_BIND_ADDR` 保持 `0.0.0.0` 是配合 NetworkPolicy，不是靠地址收敛——pod IP 网段本身内网可达，唯一的强制层就是这条策略。
4. **ServiceMonitor / 抓取配置**（第 3 段）：指标名前缀 `newapi_`，SLO 大盘与 P1 告警按 §1 #6 的 series 建；改名即视为大盘破坏性变更。ARMS 托管版可能只需 Service 注解，不必建 CR。
5. **WAF 白名单**：确认 `/healthz`、`/readyz` 不被 CC 防护和 Bot 管理拦截（探针不带 UA 特征，容易被误伤）。
6. **任务 54 联动**：`MIGRATE_MODE=off` 只在 golang-migrate 的 Job 确认接管后才能打开。
7. **SLA 口径回写**：若 G8 晚于灰度，v2.0 指南 §2242/2386/3304/4256 处的探针降级口径要按实际延迟天数如实下调，不能沿用"已具备"的表述。
