# 裸 IP 直访「白屏」诊断（2026-10-12 · 16:13–16:35 HKT）

> **状态**：诊断完成，**未做任何变更**（服务端无故障，无需修复）。
> **一句话**：`http://8.212.161.49` 服务端一切正常；白屏是**浏览器把裸 IP 升级到 HTTPS** 后撞上 `*.likha.hk` 证书不匹配导致的 —— 443 今天才上线，所以是"今天才出现"。

---

## 1. 现象

用户报告：直接访问 `http://8.212.161.49` **白屏**（此前可用）。

## 2. 服务端实测：完全正常

| 检测项 | 结果 |
|---|---|
| `http://8.212.161.49/` | **200**，1047 B，`text/html; charset=utf-8`，完整 SPA HTML（`<div id="root">`） |
| `http://8.212.161.49/api/status` | **200**，正常 JSON |
| `http://8.212.161.49/static/js/index.a499440fbb.js` | 可达（4.7 MB） |
| `http://8.212.183.7/`（另一个 AZ 的 IP） | 同样 **200** |
| 响应头 `Strict-Transport-Security` | **无**（排除 HSTS 强制升级） |
| 响应头 `Location` | **无**（裸 IP 的 80 不跳转） |
| 带浏览器 UA 请求 `/` | **200**，1047 B（与 curl 默认 UA 一致 ⇒ 无 UA 分支） |

⇒ **HTTP 路径（80 监听）没有任何问题。**

## 3. 真浏览器复现（Chrome headless，`--dump-dom` 后统计 `#root` 内容长度）

| 场景 | DOM 字节 | `#root` 内容长度 | 判定 |
|---|---|---|---|
| `http://8.212.161.49/` | 67,152 | **49,880** | ✅ 正常渲染 |
| `https://8.212.161.49/` | **0** | 0 | ❌ 证书错误，页面根本没加载 |
| `https://8.212.161.49/` + `--ignore-certificate-errors` | 1,053 | **0** | ❌ **拿到 HTML 但 React 没渲染 = 白屏** |
| `https://www.likha.hk/` | 67,152 | **49,880** | ✅ 正常渲染 |

**关键**：即使忽略证书错误，`https://8.212.161.49/` 的 `#root` **仍是 0** —— 因为 HTML 里引用的 `/static/js/*` 是**逐个子资源做证书校验**的，同样被拒 ⇒ 4 个 JS bundle 全部加载失败 ⇒ React 无脚本可执行 ⇒ **白屏**。

（对照：http 与 https-www 的 DOM 字节数与 `#root` 长度**完全一致**（67152 / 49880），证明**页面对 IP 和域名没有任何差异化逻辑**，唯一变量就是 HTTPS 证书。）

## 4. 证书事实

```
$ curl -sS https://8.212.161.49/ -o /dev/null -w '%{http_code}'
curl: (60) SSL: no alternative certificate subject name matches target host name '8.212.161.49'

$ openssl s_client -connect 8.212.161.49:443 </dev/null | openssl x509 -noout -subject -ext subjectAltName
subject = CN = *.likha.hk
X509v3 Subject Alternative Name:
    DNS:*.likha.hk, DNS:likha.hk
```

- 浏览器对 IP 字面量**不发送 SNI**（RFC 6066 禁止）⇒ ALB 用 443 监听的**默认证书** `*.likha.hk` 应答。
- 该证书 SAN **不含 IP** ⇒ 任何做证书校验的客户端（= 所有浏览器）一律拒绝。

## 5. 根因链

1. 浏览器把 `8.212.161.49` 升级为 HTTPS（地址栏自动补全 / HTTPS-First / 书签是 https / 浏览器安全策略）—— 本机默认浏览器是 **QQ Browser**，其升级策略与 Chrome 同源。
2. ALB 443 默认证书 `CN=*.likha.hk`，SAN 无 IP ⇒ **证书校验失败**。
3. 表现分两种：未忽略 ⇒ `ERR_CERT_COMMON_NAME_INVALID` 拦截页；忽略后 ⇒ 主 HTML 加载但 `/static/js/*` 全部失败 ⇒ **白屏**。
4. **为什么"今天才出现"**：443 监听是**今天（2026-10-12）**随任务 19/25 闭环才上线的（`lsn-hjl2cz2g9oqvee4eix` / `lsn-iqn5i233mvv7eu4u6w`）。
   - **443 上线前**：`https://8.212.161.49` 握手直接失败（连接被拒）⇒ 浏览器**回退到 http** ⇒ 正常。
   - **443 上线后**：握手**成功**但证书错 ⇒ 浏览器**不会回退**（证书错误 ≠ 连接不可达）⇒ 白屏。

## 6. 可解性分析（为什么这不是"配错了"）

| 可能的方案 | 可行性 |
|---|---|
| 给 ALB 443 挂一张含 IP SAN 的证书 | ❌ 阿里云 CAS 的 DV 证书**不签发 IP SAN**；IP 证书需 OV + IP 所有权证明，而 `8.212.161.49` 是 **ALB 的共享资产**，无法提供。 |
| 自签名 / 私有 CA 的 IP 证书 | ❌ 浏览器不信任该 CA，仍然报错。 |
| 在 ALB 上对无 SNI 的连接"拒绝握手"以触发浏览器回退 http | ❌ ALB 的 HTTPS 监听**必须有默认证书**，SNI 不匹配时只能回落默认证书，不支持"拒绝未知 SNI"。 |
| 把 443 关掉（回退到 443 上线前状态） | ❌ 域名业务依赖 443（任务 19/25 的成果）。 |
| **裸 IP 使用 HTTP** | ✅ 服务端已支持且完全正常（实测 200 + 正常渲染）。 |
| **生产入口统一用域名** | ✅ **推荐**。 |

⇒ **公网裸 IP 的 HTTPS 本质上无解**（除非拿到一张 IP 证书，而阿里云不提供）。这与 10-06 裁定 A「保留裸 IP 直访」并不矛盾 —— 那条裁定在 HTTP 下依然成立，但**必须补一句限定：裸 IP 仅支持 HTTP**。

## 7. 建议

1. **对外口径**：服务入口统一 `https://www.likha.hk`（canonical 已收敛，`http://ligka.hk` / `https://likha.hk` 均一跳到位）。
2. **裸 IP 直访仅在 HTTP 下保证**（`http://8.212.161.49`），这是 10-06 裁定 A 的真实边界，已补进 REFERENCE。
3. **对已访问过 https 版本的浏览器**：可能残留 HSTS/证书例外记录，需清站点数据后才可能回退 —— 因此**不建议把裸 IP 作为任何对外交付的入口**。
4. **关联项**：任务 47（Host 收敛 / 伪造 Host 404）落地后，裸 IP 的 HTTP 兜底规则若被收敛掉，则裸 IP 直访将**整体消失**。届时需与用户确认是否彻底放弃裸 IP 入口。
