# WAF 接入决策依据 · CC 攻击分类与计费选型

**日期**：2026-10-10
**用途**：本文给出攻击面分类、现有防线覆盖情况、两种计费模式的成本结构，供购买决策与后续规则配置复用。

> **证据分级约定**（全文按此标注，避免把推算当实测）
> - **[代码]** = 本仓库源码实测读得，含 `file:line`
> - **[现网]** = 阿里云/集群只读 API 实测回显

---

## 1. CC 是什么：判据层面的定义

CC（Challenge Collapsar）**不是带宽型 DDoS**。区分方式看计量单位：

| | 带宽型 DDoS | CC（应用资源消耗型） |
|---|---|---|
| 请求合法性 | 伪造/垃圾包 | **完全合法的 HTTP 请求** |
| 杀伤计量 | bps / pps | **单位请求的服务端成本** |
| 打满的东西 | 管道 | CPU、连接槽、DB 连接、**上游 LLM 配额**、账单 |
| 识别难度 | 流量异常易检 | 与真实用户行为同形，**按 IP 计数无法识别** |

结论：**CC 的防线必须能在"凭证之前"按 IP 与行为特征丢弃流量**。这是 WAF 在本项目里不可替代的唯一理由（第 4 节展开）。

## 2. 攻击分类（按消耗的资源维度）

### A. 连接占用型（慢连接 / 长流不退）

打并发连接数，不是请求数。

- **落点**：SSE 流式响应（`/v1/chat/completions`、`/v1/messages`）、`/v1/responses` WebSocket、`/v1/realtime` —— 一条连接占一个 goroutine + 上下游双向 copy + 一个 ALB 连接槽。**[代码]** `router/relay-router.go:71-88`
- **放大器**：ALB `requestTimeout` 本项目显式设 180s（指南裁定 5）⇒ 单条连接可被合法占住 180 秒。
- **现有防线**：仅 HPA 与 ALB 连接数。**应用侧只有固定窗口 QPS 限流，没有按 IP / 按 token 的并发上限**。**[代码]** `middleware/rate-limit.go:147-172`
- **归属**：WAF 侧连接/频率特征才能压住。

### B. 计算放大型（AI 网关特有，单请求成本最高）

1 个请求 → N 倍上游真实成本。

- **落点**：所有 relay 入口经 `Distribute()` 选渠道并**真实调用上游 LLM**。放大因子来自请求体：`max_tokens` 拉满、超长 prompt、`n>1`、图像张数 / 视频秒数（task plugin 按张按秒计费）。
- **现有防线**：额度预扣 + `SystemPerformanceCheck`（CPU/内存超阈值直接 503 熔断）**[代码]** `middleware/performance.go:41-59`；`ModelRequestRateLimit`（按 token/分组，含 total 与 success 两档）**[代码]** `middleware/model-rate-limit.go:175-207`
- **⚠ 关键缺口**：`ModelRequestRateLimitEnabled` 代码默认值 **`false`**（靠库里的 option 打开）**[代码]** `setting/rate_limit.go:21`、`model/option.go:445`。**现网是否真开着尚未取证 [待确认]** —— 这道防线比 WAF 更早该确认。

### C. 匿名可达的贵接口（绕过全部额度防线）

不需要 token ⇒ B 类所有额度防线失效。

- **落点清单 [代码]** `router/api-router.go:45-60,77-85`：`/user/login`、`/user/register`、`/oauth/:provider`、`/oauth/state`、`/oauth/telegram/bind/:flow_token`、`/setup`、`/epay/notify`、`/stripe/webhook`、`/creem/webhook`、`/waffo/webhook`
- **消耗**：口令哈希 CPU 密集；登录额外打 Turnstile 外部调用；`/oauth/:provider` 打第三方 IdP。
- **现有防线**：`CriticalRateLimit` = **20 次 / 1200 秒，按客户端 IP**。**[代码]** `common/init.go:131-133`
- **缺口**：按 IP ⇒ **僵尸网络换 IP 即穿透**。这是任务 20「CC 阈值 + 人机校验」唯一不可替代的位置。

### D. 大请求体型（内存与解析）

- **落点**：`/v1/audio/transcriptions`、`/v1/images/edits`（multipart base64）、**解压炸弹**（`Content-Encoding: gzip/br/zstd` 小压缩体解成大体积）。
- **已有硬顶 [代码]**：解压后按 `MAX_REQUEST_BODY_MB` 截断，默认 **128 MB**（`common/init.go:184`、`middleware/gzip.go:26-41` 用 `http.MaxBytesReader` 强制）；匿名路径另有 **512 KB**（`ANONYMOUS_REQUEST_BODY_LIMIT_KB`，`common/request_body_limit.go:5`、`common/init.go:185`）。
- **残余风险**：128 MB × 并发 = OOM 路径。`SystemPerformanceCheck` 是**事后熔断**不是**事前准入**，两者不等价。

### E. 查询/扫描型（把 CC 打成数据库不可用）

- **落点 [代码]**：`/api/usage/`、`/api/log/`（挂 `CriticalRateLimit`，`router/api-router.go:290,346`）、`/api/token/search` 与 `/api/log/self/search`（`SearchRateLimit` = **10 次 / 60 秒**，`api-router.go:278`、`common/init.go:135-137`）、`/api/ratio_config`、定价大列表。
- **杀伤路径**：慢查询占住连接 ⇒ 主库经 PgBouncer 只有 `SQL_MAX_OPEN_CONNS=100`（10-06 裁定）⇒ **正常业务拿不到连接**。这类攻击不需要打垮容器，只要让连接池空转就赢。
- 日志库侧另有 CK 跨区扫描成本（备站→马尼拉 RTT 实测 37 ms **[现网]**）。

### F. 轮询风暴型（任务状态查询）

- **落点 [代码]**：`/mj/task/:id/fetch`、`/mj/task/:id/image-seed`、`/mj/task/list-by-condition`（`router/relay-router.go:224-226`）、图片/视频任务轮询。
- **消耗**：每次轮询 = 一次 DB 读，部分实现会再去上游查状态（跨区、跨厂商）。
- **已有针对性防线 [代码]**：`TASK_ARTIFACT_INVALID_RATE_LIMIT_PER_MINUTE` 默认 **60/min**（`setting/system_setting/task_artifact.go:6-13`）。它按"**无效访问**"计数，防的是拿别人的 task id 试探存在性 —— 设计方向正确。

### G. 缓存穿透型（当前不适用）

带随机 query 参数打穿边缘缓存，让全量回落到 Go + DB。**本项目未启用 DCDN ⇒ 这一类当前不存在**；一旦启用 DCDN 即新增，且必须同步回源网段（任务 47 条件规则）。

### H. 上游配额耗尽型（杀伤点在第三方，最贵）

攻击者不需要打垮我们任何一台机器，只要把 40+ provider 的 RPM/TPM 配额吃满：

1. 正常用户全部 429/503；
2. **`Distribute()` 的渠道重试会二次放大** —— 一个失败请求变成对多个渠道的多次上游调用；
3. 账单面即 §14 成本表坑 2「一次 CC 攻击把 WAF 请求数打到天价」。

**这是唯一同时造成"服务不可用 + 真金白银损失"的形态，且应用层限流救不了**（请求带合法 token、合法额度，在应用看来完全正常）。

### I. 反射放大型（明确不适用）

需要 UDP 与可欺骗源协议，HTTP 网关不是这个形态。列出来是为了防止按带宽型思路配防护 —— 那会白花钱。

## 3. 分层防御映射：哪一层拦哪一类

| 层 | 本项目实际有的 | 位置 | 拦得住 | 拦不住 |
|---|---|---|---|---|
| **准入（认证前，按 IP/行为）** | ⚠ 仅 `CriticalRateLimit` 20/1200s | `common/init.go:131-133` | C、H 的匿名部分 | A、B、E、F 全不在射程 |
| 认证 | Turnstile + `CriticalRateLimit` | `api-router.go:77-85` | C | 换 IP 的僵尸网络 |
| 授权（按 token/分组） | `ModelRequestRateLimit`（**代码默认关**） | `model-rate-limit.go:175-207` | B、F | 匿名流量（排在 `TokenAuth` 之后） |
| 资源 | 额度预扣、`SystemPerformanceCheck` 熔断、HPA、池 100 连接 | `performance.go:41-59` | B、D、E 的下限 | 已经造成的成本 |
| 上游 | 渠道重试、600s 硬上限 | `Distribute()` | — | **H（重试反而放大它）** |
| **WAF CC + 人机校验** | ⚠ **未购** | 任务 20 | A、C、E、F、H 的**源头压制** | — |

**一句话结论**：WAF 那层是唯一能在**凭证之前**按 IP 和行为特征丢弃流量的。砍掉它 ⇒ C/D/E/F 四类匿名靶子全靠按 IP 的 20/1200s 兜着，僵尸网络换 IP 即穿透；保留它 ⇒ 买的是"未持凭证的流量不要打到 Go、不要打到上游配额"。

## 4. 计费选型：包年包月 vs 按量付费

### 4.1 两种模式的费用结构

> 单价 **[文档]**：1 SeCU = 0.01 USD（国际站按量示例口径）；包月高级版大陆标价 3,880 元/月。**这些是标价推算，不是本账号实测报价。**

| 计费项 | 按量付费 | 包年包月高级版 |
|---|---|---|
| 实例常驻 | 0.5 SeCU/h ≈ **$3.6/月**（开通即计，不配置也收） | 含在 $556 |
| Web 核心防护默认模板 | 存在防护对象即 **10 SeCU/h ≈ $72/月** | 含 |
| CC 防护规则 | **2 SeCU/规则/h ≈ $14.4/月/条**，⚠ **启用与禁用状态都计费** | 含 |
| QPS | ≤1,000 QPS 免费；超出 **1 SeCU/5 QPS/h** | 版本内 **2,000 QPS** 免费 |
| **请求数** | **1 SeCU/5,000 请求/h，无上限** | 版本内 QPS 覆盖，超出走弹性后付费 |
| 日志服务 | 单独计费 | 单独增值模块（大陆标价 500 元/TB/月，**最小 3TB 起购**）**[待确认]** |
| Bot 管理（若人机校验归此模块） | **50 SeCU/模板/h ≈ $360/月** + 请求处理费 1 SeCU/7,500 请求/h | 需确认是否含 **[待确认]** |
| CNAME 接入域名数 | 阶梯：1 域名 0 SeCU；2~10 域名 5 SeCU/域名/h | 高级版含 5 个，可扩 500 |

⚠ **本项目走 ALB 云原生接入，防护对象是 ALB 资源本身而非域名 ⇒ 不消耗"可接入域名数"配额，`域名扩展` 填 0**（官方文档明确云原生模式按防护对象数计，300–10,000 按版本）。

### 4.2 版本选择：高级版是下限，基础版做不出本卡判据

| 版本 | 大陆标价/月 | QPS | 域名数 | CC 防护 | 自定义规则 | 日志服务 | 端口 |
|---|---|---|---|---|---|---|---|
| 基础版 | 980 元 | **10** | 3（扩 10） | ✗ | ✗ | ✗ | 标准 |
| **高级版** | **3,880 元** | **2,000** | 5（扩 500） | ✅ | ✅ | 付费开通 | 标准 |
| 企业版 | 9,800 元 | 5,000 | 10（扩 2,000） | ✅ | ✅ | 付费开通 | 含非标 |
| 旗舰版 | 29,800 元 | 10,000 | 50（扩 5,000） | ✅ | ✅ | 付费开通 | 含非标 |

- **基础版不可用**：不支持 CC / 自定义规则 / BOT / 日志 ⇒ 任务 20 判据③④⑤ 物理做不出来；且 10 QPS 硬顶，光 kubelet 对 `/api/status` 的探针实测就 ~195 req/min ≈ 3.3 QPS **[现网 10-08]**，加两地 ALB 与站点监控探测会直接顶穿。
- **企业版对本卡无必要**：多出来的是非标端口、5,000 QPS 基线、更多防护对象，任务 20 一条都不用。
- ⇒ **停在高级版**。

### 4.3 攻击态算术（决策的核心）

**稳态**：本项目真实流量极小 —— `sls-newapi-mnl/alb_access` 24h 实测 stable 只有 `/` 1,095 条 + `/api/status` 41 条 **[现网 10-08]**（ALB 访问日志不含健康检查）。按量粗算 ≈ **$94/月**（实例 + 核心防护 + 1 条 CC + 流量，不含日志），是包月 $556 的约 **1/6**。

**攻击态才是分水岭**：按量下每一百万个打到防护对象的请求 = **$2，包括被 WAF 拦掉的**。

| 场景 | 按量付费 | 包月高级版 |
|---|---|---|
| 日常（<1,000 QPS） | ≈ $94/月 | $556/月 |
| 持续 100 QPS 攻击 | ≈ $520/月增量 | **$0 增量** |
| 持续 2,000 QPS 攻击 | ≈ **$10,400/月增量** | **$0 增量**（落在版本内 2,000 QPS 基线） |
| 持续 5,000 QPS 攻击 | 更高，无上限 | 超出版本内部分走弹性后付费（有单价，可控） |

**⇒ 按量付费把"被攻击"变成了"被扣款"，而我们买 WAF 就是为了被攻击的那天。**

### 4.4 按量模式独有的运维风险

1. **欠费即停服**，每日结算（UTC+8）。WAF 是 SDK 集成在 ALB 上的，**停服时入口行为如何变化（fail-open 还是 fail-closed）文档未写 [待确认·建议工单]**。本项目已有 RDS + 马尼拉 Tair **2026-10-28 到期**这条续费风险线，再叠一条日结后付费 = 多一个静默裸奔的口子。
2. **规则常驻计费且禁用状态也收钱** —— 演练期临时建的 CC/自定义规则，忘删就一直挂在账单上。
3. **切换不可逆**：按量实例释放会带走规则配置，将来转包月要重建。

### 4.5 最后结论

**当前 $556 超预算**：目前商量结论是**把 WAF 延后**，等真实流量与预算明朗再买。
