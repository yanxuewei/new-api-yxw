## 一、SLO 定义（对外/对内同源）

| SLO | 指标 | 目标 | 窗口 | 数据源（实测） | 状态 |
|---|---|---|---|---|---|
| 可用性 | 外部拨测成功率 | **99.95%** | 月 | 云监控站点监控 `likha-hk-newapi-status`（4 探针） | ✅ 在用 |

| 请求成功率 | 自身 5xx 比例（排除 4xx/429、**排除上游 5xx**） | **≥99.9%** | 5min 滑窗 | SLS `sls-newapi-mnl/alb_access`（`host`/`status`/`upstream_status`） | ✅ 可算（已建 3 条告警） |

| 网关链路 | 上游 5xx（`upstream_status ≥ 500`） | 单独曲线 | 月 | 同上（`up_pct` 字段） | ✅ 可查，**不计入自身 SLO**（§12 排除项③） |
| DB | 慢查询 >1s | 阈值告警 | 5min | RDS/PG 监控（另线） | 沿用现有 |

**口径纪律**：5xx 的唯一真源 = `alb_access`（ALB 日志**不含健康检查**行，分母=真实用户流量，任务 27 坑 15）；
Grafana 不做 5xx 面板，避免两处口径打架。

## 二、错误预算燃烧率（已落地：3 条 SLS 告警）

`deploy/tasks/task32/burn_alerts.sh`（幂等，`--status/--dump/--apply`）：

| 规则 | 窗口 | 判据（自身 5xx 率） | 等价燃烧率 | severity | 评估间隔 |
|---|---|---|---|---|---|
| `newapi-slo-burn-rapid-p1` | 1h | `own_pct > 0.72` | 14.4× | **8（P1）** | 1m |
| `newapi-slo-burn-mid-p2` | 6h | `own_pct > 0.30` | 6× | 6（P2） | 5m |
| `newapi-slo-burn-slow-p3` | 3d | `own_pct > 0.05` | 1×（按 SLA 速度消耗） | 6（P3 排期处理） | 30m |

SQL（一次查出 5 个量，避免多次扫描）：

```sql
host: www.likha.hk | select count(*) as n,
  sum(case when status >= 500 then 1 else 0 end) as e5xx,
  sum(case when status >= 500 and coalesce(upstream_status, 0) < 500 then 1 else 0 end) as own5xx,
  round(sum(case when status >= 500 and coalesce(upstream_status, 0) < 500 then 1 else 0 end) * 100.0 / count(*), 4) as own_pct,
  round(sum(case when coalesce(upstream_status, 0) >= 500 then 1 else 0 end) * 100.0 / count(*), 4) as up_pct
```

> ★ 两个实测坑：① `coalesce(upstream_status,'0')` 报 `All COALESCE operands must be the same type: bigint` ⇒ 必须写 `coalesce(upstream_status, 0)`；② `CreateAlert` 拒收富 body ⇒ 两段式（先最小 body 建，再 `UpdateAlert` 全量覆盖），沿用任务 27 坑 16。
> ⚠ **这 3 条规则目前只有本体、没有通知渠道/行动策略** ⇒ 触发不会通知任何人（见第四节）。

## 四、⛔ P1「电话」通道：国际站结构性不可用（实测）

`aliyun cms PutContact` 元数据明写：**intl 只支持「邮箱」或「钉钉机器人」**（china 才有 phone/SMS）。
⇒ 卡片原设计的「云监控告警 + 电话通道」在**国际站无法实现**，命中卡片自带的「不通过时修复」分支。

候选（详见 `P1电话通道_实测与选型_2026-10-19.md`）：

| 方案 | 电话能力 | 成本 | 落地复杂度 | 备注 |
|---|---|---|---|---|
| A 钉钉群 + 云监控邮件 | ❌ 无电话 | 0 | 低 | 不满足 P1 要求，仅作 P2/P3 |
| B 第三方 on-call（PagerDuty/Better Stack 等） | ✅ 语音呼叫 + 升级链 | ~$0–30/月 | 中（webhook 接入） | **推荐**：SLS/云监控 webhook → on-call → 电话 |
| C 自建 webhook 中转（ops 节点） | ✅（需接语音 API） | 语音 API 费用 | 高（要写服务+高可用） | 仅当不愿引入第三方 |

## 五、发布冻结决策（接燃尽曲线）

| 月累计预算消耗 | 动作 |
|---|---|
| < 25% | 正常发布 |
| **> 25%** | **只允许修复类变更**（bugfix/回滚/配置纠错），功能发布顺延 |
| **> 50%** | **冻结**，任何变更需架构负责人书面签字例外 |
| 解冻 | 连续 **7 天**燃烧率 <1× 且复盘（RCA）关闭 |

判定脚本（人工月度检查，数据同 §二 SQL，窗口改 `-30d`）：

```bash
FROM=$(date -d '-30 day' +%s); TO=$(date +%s)
aliyun sls GetLogsV2 --project sls-newapi-mnl --logstore alb_access --region ap-southeast-6 \
  --body "{\"from\":$FROM,\"to\":$TO,\"query\":\"host: www.likha.hk | select count(*) as n, round(sum(case when status>=500 and coalesce(upstream_status,0)<500 then 1 else 0 end)*100.0/count(*),4) as own_pct\",\"line\":1}"
# 预算消耗% = own_pct / 0.05 * 100
```
