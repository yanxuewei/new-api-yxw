## 二、错误预算燃烧率（已落地：3 条 SLS 告警）

`deploy/tasks/task32/burn_alerts.sh`（幂等，`--status/--dump/--apply`）：

| 规则 | 窗口 | 判据（自身 5xx 率） | 等价燃烧率 | severity | 评估间隔 |
|---|---|---|---|---|---|
| `newapi-slo-burn-rapid-p1` | 1h | `own_pct > 0.72` | 14.4× | **8（P1）** | 1m |
| `newapi-slo-burn-mid-p2` | 6h | `own_pct > 0.30` | 6× | 6（P2） | 5m |
| `newapi-slo-burn-slow-p3` | 3d | `own_pct > 0.05` | 1×（按 SLA 速度消耗） | 6（P3 排期处理） | 30m |

SQL（一次查出 5 个量，避免多次扫描）：

```sql
host: www.likha.hk | select count(*) as n,
  sum(case when status >= 500 then 1 else 0 end) as e5xx,
  sum(case when status >= 500 and coalesce(upstream_status, 0) < 500 then 1 else 0 end) as own5xx,
  round(sum(case when status >= 500 and coalesce(upstream_status, 0) < 500 then 1 else 0 end) * 100.0 / count(*), 4) as own_pct,
  round(sum(case when coalesce(upstream_status, 0) >= 500 then 1 else 0 end) * 100.0 / count(*), 4) as up_pct
```

> ★ 两个实测坑：① `coalesce(upstream_status,'0')` 报 `All COALESCE operands must be the same type: bigint` ⇒ 必须写 `coalesce(upstream_status, 0)`；② `CreateAlert` 拒收富 body ⇒ 两段式（先最小 body 建，再 `UpdateAlert` 全量覆盖），沿用任务 27 坑 16。
> ⚠ **这 3 条规则目前只有本体、没有通知渠道/行动策略** ⇒ 触发不会通知任何人（见第四节）。
