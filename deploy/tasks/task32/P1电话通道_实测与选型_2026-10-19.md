# P1「电话」告警通道 · 复核与结论（2026-10-19 **修订版**）

> 原版（同日午前）结论「国际站结构性不可用」——**错误，已作废**。
> 本文保留错误路径与纠正证据，避免下次再踩同一个坑。

## 一、错误结论是怎么来的（两个坑，都在我这侧）

1. **查错 API 版本**：用经典 `aliyun cms DescribeContactList`（API 2019-01-01）查联系人 ⇒ 三地域全返回 `count=0`，
   于是判定「联系人没建」。实际控制台「通知对象」属于**云监控 2.0（`cms2`，API 2024-03-30）**，
   两套存储互不可见。正确命令：
   ```bash
   aliyun cms2 notification-channel contact list --region ap-southeast-1 -o json
   ```
2. **误读元数据**：`cms PutContact` 的 `intl` props 写「只支持 邮箱 / 钉钉」，我据此推断「国际站无电话/SMS」。
   那是 **1.0 的联系人创建接口**；2.0 的联系人**本身就带手机号**，官方《通知对象》明确
   「联系人支持通过**电话、短信和邮件**方式接收告警通知」。

## 三、结论

**P1 电话在阿里云国际站可行**，路径 = `云监控2.0 告警规则（cms2，SLS/Prometheus 数据源）`
+ `通知策略（电话+短信+邮件，绑 ack_Default Contact Group）`。
卡片原设计成立，**不需要第三方 on-call，也不需要自建中转**。

## 四、落地步骤（1 个人工动作 + 我接力）

**人工（控制台，约 3 分钟）**

1. 云监控2.0 → 告警中心 → 通知管理 →「通知策略」→ 新建：
   - 名称：`newapi-p1-voice`
   - 通知对象：联系人组 `ack_Default Contact Group`
   - 通知方式：**电话 + 短信 + 邮件**（P1/CRITICAL）
   - 升级：未响应 5 分钟 → 追加通知（第二值班 / 负责人）
2. 把**策略标识符（ID）**发我。

**我接力（拿到 ID 后）**

1. `cms2 alert rule create` 建 3 条 **SLS 数据源**规则（燃烧率 1h/6h/3d，判据同 `burn_alerts.sh`），
   `notifyConfig.notifyStrategies=[<策略ID>]`；
2. 视需要启用 ACK addon 的节点类规则（CPU/磁盘/NotReady）并绑同一策略，作为 P2 底座；
3. **V1 触发实测**：新规则判据临时改「恒真」+ `severity=CRITICAL` → 触发一次 → 记录电话/短信到达时间
   （≤3 min 合格）→ 立刻改回正式判据；
4. 结果回写运行手册 §七 与本文末尾。

## 五、遗留风险（如实记）

- **计费**：电话/短信超免费额度按量；只让 CRITICAL 走电话。
- **通知策略只能控制台建**（CLI 无命令）⇒ 半自动环节，换人/重建时要记得。
- **站点不可用 P1 在 1.0**（站点监控）：其电话语音是 1.0 默认集成（联系人组 + Critical），与 2.0 策略是两套，验收要分别测。
