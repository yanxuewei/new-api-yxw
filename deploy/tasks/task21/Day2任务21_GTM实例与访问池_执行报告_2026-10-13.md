### ★ 成本（卡片未列，必须补）

GTM 3.0 按量付费四计费项（国际站 USD）：接入域名 `0.015/个/天` · 解析 `0.004/万次` · **健康探测 `1.5/万次`** · 短信告警 `0.225/条`。

探测次数 = `地址数 × 探测节点数 × (86400 ÷ 间隔)` ⇒ **本次配置（1 地址 × 3 节点 × 60s）**：

| 计费项 | 用量 | 月费 |
|---|---|---|
| 接入域名 | 1 个保留 | **0.45 USD** |
| 健康探测 | 1×3×1440 = 4,320 次/天 → 12.96 万次/月 | **19.44 USD** |
| 域名解析 | 假设 10 万次/天 → 300 万次/月 | **1.20 USD** |
| **合计** | | **≈ 21 USD/月** |

⚠ **间隔与地址数是两个成本乘数**：15s ⇒ ≈78 USD/月；IPv4 池放 2 个 EIP ⇒ 探测费 ×2。
本次取 **60s + 单地址（domain 池）**，是「满足任务语义」与「成本可控」的平衡点（用户 2026-10-13 裁定）。

⚠ **禁用不禁费**：禁用接入域名后，其下探测任务**仍在执行并计费**；要彻底停费须 `teardown` 或删除探测任务。

## §4 关键技术坑（本轮实踩）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **CLI 传不了 GTM 的数组参数** | `aliyun alidns CreateCloudGtmMonitorTemplate --IspCityNodes.1.CityCode 569 …` → 本地报 `required parameters not assigned: --IspCityNodes` | 这批参数的 meta 标 **`"style": "json"`** ⇒ 数组要**整体传 JSON 串**：`IspCityNodes='[{"CityCode":"569","IspCode":"465"},…]'`。CLI 点号展开**不适用于 style=json 参数** |
| 2 | **CLI 元数据缺失的接口** | `CreateCloudGtmInstanceConfig` / `CreateCloudGtmAddressPool` / `Update*` 空调用时 CLI 回**产品级帮助**（不是参数错误）⇒ 无法据此判断必填项 | 改查官方 OpenAPI 元数据：`https://api.aliyun.com/meta/v1/products/alidns/versions/2015-01-09/apis/<Action>/api.json`（含 `required` / `style` / `enum` / items 结构），或直接用 `deploy/lib/aliyun_rpc.py` 按扁平明文提交 |
| 3 | **`wsl bash -c` 内 shell 变量被吞** | `for c in A B; do aliyun $c …` 中 `$c` 展开为空 ⇒ 命令退化成 `aliyun alidns`（打印产品帮助），看起来像"API 不认识" | 项目既有铁律：**多行/带变量脚本一律先落盘成文件**再 `bash /mnt/e/.../x.sh`（本轮 `t_gtm_01.sh` 复现过一次） |
| 4 | **`--help` 对这批 API 无效** | `aliyun alidns <Action> --help` 输出产品级帮助而非参数签名 | 同上，走 meta 元数据 |
| 5 | **`MonitorTaskQuota: 0` 不等于"不能探测"** | 实例属性 `MonitorTaskQuota=0`、`DescribeCloudGtmSummary.MonitorTaskTotalQuota=0`，一度怀疑探测被禁用 | 实测 `MonitorTaskTotalCount` 从 0 → **1**（任务已建、已计费）⇒ 该字段是**预付费口径**，后付费实例按量计费不受其约束 |
