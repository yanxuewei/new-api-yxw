## 1. 结论（TL;DR）

SG ALB（备站）现在对 `www.likha.hk` / `likha.hk` 的处理**与 mnl 逐字节对齐**：

| 入口 | SG（本次对齐后） | mnl（对照） |
|---|---|---|
| `http://likha.hk` | 301 → `https://www.likha.hk` | 同 ✅ |
| `http://www.likha.hk` | 301 → `https://www.likha.hk` | 同 ✅ |
| `https://likha.hk` | **308** → `https://www.likha.hk` | 同 ✅ |
| `https://www.likha.hk` | 200（**不跳转**，走兜底 → 备站业务） | 同 ✅ |

**为什么必须做**：SG 原本**只**监听 80 有兜底、443 只有两条显式 Host 规则 ⇒ 一旦 DNS 切到 SG（DR），`https://www.likha.hk` 会落监听器默认动作（派生占位组）⇒ **502**；而 `https://likha.hk` 的 308 会把用户导向一个 502 地址 —— 规范化跳转反而制造故障。对齐后该风险消除。

## 3. 执行序列（★ 次序不可颠倒）

| 步 | 动作 | 为什么这个次序 |
|---|---|---|
| **A** | 先给 `new-api-ph-standby-ip` 补 `{"HTTPS":443}` + `order:"50"` | 若**先**做 canonical，`https://likha.hk` → 308 → `https://www.likha.hk` 会因 SG 443 **无兜底**而落占位组 ⇒ **502**（规范化跳转把人送进故障页） |
| **B** | 再 apply `-sg-http-redirect`（80）+ `-sg-https-canonical`（443） | 兜底已就位，canonical 的跳转目标必然可达 |

中间态验证（Step A 后、Step B 前）：`https://www.likha.hk` 指向 SG 两 IP → **200 不跳转** ✅（证明兜底工作）。

## 5. 关键技术结论

1. **★ 次序是硬约束**：SG 侧必须「**先补 443 兜底、后上 canonical**」。反过来会制造「308 指向 502」的短暂故障窗口。（同 mnl 的「先探针后上线」思路：先让目标可达，再做跳转。）
2. **★ 与 mnl 完全对称的拓扑**（见 §2 表）—— 今后两地任何一处改域名策略，另一处照抄即可，心智模型统一。
3. **★ RuleId 再次漂移**（本日第 2 次实测）：80 的 `rule-an94dmm2qm60em54bw` 原属 `sg-standby.internal`、443 的 `rule-5qc042unqehclbul67` 同源，本次均被重assign 给新规则；兜底规则 ID 也从 `rule-bbk2hlv7sgu7j28obs` 变为 `rule-vz9gxy1830bw4vc9pn`。⇒ **判路由一律实时查 API**。
4. **`order` 缺省值 = 10**：未设 `order` 的 Ingress 落在 10；`order=1` 足以压过显式 Host（10）与兜底（50）。本次同时给兜底显式 `order:"50"`，与 mnl 对齐并消除「同 order 相对顺序不确定」的隐患。
5. **`new-api-ph-standby-ip` 的「吃掉所有未匹配 Host」特性**本次是**设计要求**（www 有意不建显式 Host 规则，就是要落兜底 ⇒ 不跳转、直出业务），与 mnl 的 www 行为一致 —— 原文件头注中「将来加第二个域名须重新评估」已按此结论复核并更新。
