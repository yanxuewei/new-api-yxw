## 4. ★ 本次三条关键技术发现

### 4.1 `certificates[].CertificateId` 才是正确字段名（原文档写错）

AlbConfig 的 listener 证书条目：

```yaml
certificates:
  - CertificateId: 606823-ap-southeast-1   # ✅ 字段名 = CertificateId；值 = CertIdentifier
    IsDefault: true
```

- 原 `albconfig.yaml.tpl` / 指南 §任务19 步骤 2 写的是 `- CertIdentifier: ${CERT_ID_ALB}` —— **字段名错**。
- CRD 是 `x-kubernetes-preserve-unknown-fields` ⇒ 错名**被静默忽略，不报任何错**，443 监听会建起来但**不挂证书**（或不建监听）。
- 已订正两处文档 + 两个 manifest。

### 4.2 ★★ ALB 一律拒绝直接 OpenAPI 写操作：`OperationDenied.ServiceManagedResource`

对 ACK 托管的 ALB 直接调 `alb CreateListener`（含 `--DryRun true`）**在服务端被拒**：

```
Code: OperationDenied.ServiceManagedResource
Message: The operation is not allowed because the current resource is managed resource.
```

⇒ 「管理红线（禁止控制台改 listener）」不只是纪律，而是**平台级技术强制**。同时这也意味着 **DryRun 探针法在托管 ALB 上不可用**（探测请求本身就被拒），无法用它预先验证证书参数。

同理：`aliyun alb CreateServerCertificate` / `ListServerCertificates` **不存在**（ALB 证书只有 3 个 API：`AssociateAdditionalCertificatesWithListener` / `DissociateAdditionalCertificatesFromListener` / `ListListenerCertificates`）。

### 4.3 ★★ 跨地域证书可用（推翻「必须同地域」的推断）

- 事实：`cas` 产品在 **`ap-southeast-6` 无 endpoint**（`cas.ap-southeast-6.aliyuncs.com` **DNS 不存在**；`aliyun cas --help --cli-output json --cli-query 'endpoints[].regionId'` 返回 12 个地域，**不含 ap-southeast-6**）。CAS 全局端点 `cas.aliyuncs.com` 可用。
- 但 `ap-southeast-1` 的证书 `606823-ap-southeast-1` 被 **ap-southeast-6 的马尼拉 ALB 成功 Associated**。
- ⇒ **ALB 侧不要求证书与实例同地域**；「马尼拉用不了证书」的推断不成立。无需为 mnl 另行购证或上传副本。

### 4.4 ★ ACK ALB 跳转注解的字段名坑（错名静默退化，极具误导性）

官方《自定义 ALB Ingress 的转发规则》正确写法：

```yaml
alb.ingress.kubernetes.io/actions.redirect: '[{"type":"Redirect","RedirectConfig":{"host":"${host}","path":"${path}","port":"443","protocol":"HTTPS","query":"${query}","httpCode":"301"}}]'
```

- 配置对象名是 **`RedirectConfig`（PascalCase）**，状态码键是 **`httpCode`**（不是 `statusCode`）。
- 本次先误写 `{"type":"Redirect","redirectConfig":{"statusCode":"301"}}` → **未识别、不报错**，Rules 里未出现 Redirect，反倒多出 `rule-80-5`(ForwardGroup) + `rule-80-6`(FixedResponse 404)，而 **HTTP 仍返回 200**，足以让人误判"配置生效了"。
- `type` 值 PascalCase（`Redirect`/`FixedResponse`/`ForwardGroup`），内层键 camelCase；action 名必须与 backend `service.name` 一致、`port.name = use-annotation`。

## 5. 误判复盘（一次虚惊）

排查中曾出现「全站 HTTP 404」，实为**测试方法错误**：`curl -sSI` 发的是 **HEAD**，而 new-api 的 `/api/status` 仅注册 GET ⇒ gin 返回应用层 404（`Content-Type: application/json`，106 字节）。

**教训**：区分「ALB 的 FixedResponse 404」（`text/plain`）与「应用层 404」（`application/json` + `X-Oneapi-Request-Id`）；验证 HTTP 语义一律用 GET（`curl -sS -o /dev/null -w '%{http_code}'`），不要用 `-I`。
