主要配置变更
1. JVM 应用使用 Xms64m、SerialGC、ActiveProcessorCount=1、元空间/直接内存/代码缓存限额。
2. Nacos 保留当前 standalone/Derby 数据卷，Xms128m/Xmx256m/Xmn64m；修复旧 Xmn512m 与 Xmx256m 冲突。
3. MySQL buffer pool=128 MiB、max_connections=60、performance_schema=OFF；保留事务持久化默认设置。
4. Redis maxmemory=64 MiB，noeviction；达到上限将拒绝需要额外内存的写入，不随机淘汰会话。
5. 数据源与 Redis 指向 Docker 服务名；Nacos 地址与 erp-dev 命名空间一致，补建缺失命名空间。
6. 显式监听端口：gateway 8080、user 8081、product 8082、order 8083。
7. 每应用 Hikari 最大连接数 5、最小空闲 1；Tomcat 最大线程 20、最小空闲 2。
8. 应用镜像固定为本地带日期 tag、pull_policy=never，移除错误 build 引用。
9. 日志轮转 max-size=10m、max-file=3；容器设置内存/CPU/PID 上限和自动重启。
10. 用户镜像缺 Actuator，使用 TCP 健康探针，其 healthy 不等价于成功登录。
11. 订单当前源码没有 RabbitMQ/Elasticsearch 业务引用，minimal 也没有部署两项；关闭其健康指示器与 Rabbit listener 自动启动，保留数据库/Redis 健康检查。未来启用消息队列或搜索功能时必须恢复对应配置并部署依赖。
12. 恢复已有前端镜像，127.0.0.1:3000:80，增加 erp-gateway 网络别名，兼容前端镜像已有 Nginx 上游。

重要边界
当前 minimal 数据库 erp_user.t_user / erp_order.t_order / erp_product.t_product 均为 0 行。
这是用户此前启动的独立 mysql-minimal-data 卷；本轮没有清空表或导入初始化脚本。
旧 omnitradeerp_mysql-data 及旧 Redis/Nacos 等卷全部保留，未合并或迁移数据。
因此旧管理员账号尚未迁入，当前不能声明“登录与全部业务可用”。
客户、供应商、仓储、库存、财务、物流、AI 不属于此 minimal 部署，相关界面不能据此认定可用。
保留了既有数据库凭据及端口暴露方式；本轮不构成生产安全加固验收。
