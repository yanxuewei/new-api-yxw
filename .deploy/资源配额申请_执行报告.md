### 2.2 等价 CLI（实际执行，已按实测修正参数名）

```bash
# ① 马尼拉
aliyun quotas CreateQuotaApplication \
  --ProductCode ecs-spec --QuotaActionCode q_ecs_enterprise_postpay_c \
  --DesireValue 64 \
  --Reason "new-api AI gateway production launch in Manila (ap-southeast-6), D4 node pool creation is on the critical path. ACK node pool uses ecs.g8i.2xlarge (8 vCPU): min 4 nodes = 32 vCPU steady state, max 8 nodes = 64 vCPU at peak, HPA up to 16 pods. Current postpaid enterprise vCPU quota is 50, which blocks the peak node pool size (8 nodes x 8 vCPU = 64). Requesting 64." \
  --Dimensions.1.Key regionId --Dimensions.1.Value ap-southeast-6 \
  --NoticeType 3 --QuotaCategory CommonQuota

# ② 新加坡
aliyun quotas CreateQuotaApplication \
  --ProductCode ecs-spec --QuotaActionCode q_ecs_enterprise_postpay_c \
  --DesireValue 96 \
  --Reason "new-api AI gateway standby region (Singapore ap-southeast-1). To keep the committed SLA of 99.95 percent, the standby region must take over one complete primary site at no less than 1.5x of its peak: 16 pods peak x 1.5 = 24 pods, 24 x 4 vCPU (container limit) = 96 vCPU, node pool 12 nodes x 8 vCPU (ecs.g8i.2xlarge) = 96 vCPU. The quota is region scoped, so the Manila approval does not apply here." \
  --Dimensions.1.Key regionId --Dimensions.1.Value ap-southeast-1 \
  --NoticeType 3 --QuotaCategory CommonQuota

# ③ 查状态 / 复查现值
aliyun quotas ListQuotaApplications --ProductCode ecs-spec
aliyun quotas ListProductQuotas --ProductCode ecs-spec \
  --Dimensions.1.Key regionId --Dimensions.1.Value ap-southeast-6 \
  --QuotaActionCode q_ecs_enterprise_postpay_c
```

> 申请理由**必须带可核算容量式**（vCPU 数 × 节点数 × 倍数关系）。只写「要 96 核」的驳回率显著更高 —— 本次两条理由都写足了算法与阶段（D4 建节点池 / SLA 99.95% 接管倍数）。

## 7. 脚本用法

```bash
bash quota_apply.sh probe     # 落盘全量实时值 → .workbuddy/quota/
bash quota_apply.sh check     # 只读：需求 vs 现值缺口表 + 已有申请状态
bash quota_apply.sh apply     # 提交缺口项申请（幂等：现值已达标 / 已有申请则跳过）
bash quota_apply.sh verify    # 读回状态 + 复查 TotalQuota 是否达标
bash quota_apply.sh all       # probe → check → apply → verify
```

**脚本内置的 3 个护栏**

1. **现值优先幂等**：提交前先读 `TotalQuota`，已达标直接跳过 —— 不依赖申请记录的可读性。
2. **申请记录去重**：同 `(QuotaActionCode, region)` 已有 `Process/Agree` 记录即跳过，防重复提单。
3. **参数与状态修正已固化**：`--DesireValue`（非 `DesiredValue`）、`Dimension`（非 `Dimensions`）、状态集含 `Agree`。

**踩坑记录（均已在脚本注释里标注）**

- 只传 `--RegionId` 不传 `--Dimensions` → 拿到 `cn-hangzhou` 的值（假数据）。
- `ecs-spec` 用 `regionId` 维度；`eip/csk/oss/nat/slb/alb` **不支持**该维度（传了报 `QUOTA.DIMENSION.UNSUPPORT`）→ 脚本对这两类产品走不同分支。
- `kvstore` / `rds` 报 `PARAMETER.ILLEGALL`：不是参数写错，是**产品未开通**。
