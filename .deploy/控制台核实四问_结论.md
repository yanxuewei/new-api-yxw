## 二、Q1 马尼拉 ClickHouse — 实测确认可用，但锁死单 AZ

### 2.1 实测输出

```bash
aliyun --region ap-southeast-6 clickhouse DescribeRegions
```

```json
{"RegionId":"ap-southeast-6","Zones":{"Zone":[{"ZoneId":"ap-southeast-6a","VpcEnabled":true}]}}
```

- ✅ `ap-southeast-6` **在返回列表中**

对比 ECS 侧同地域有 6a/6b 两个 AZ → **ClickHouse 在马尼拉只上了 1 个 AZ**。

三方证据一致指向：**可开通，但形态为「企业版 + OSS 存储 + 单 AZ」**。

### 2.3 结论

## 三、Q2 实例规格 — g8i 未上架，须换机型

### 3.1 实测方法

```bash
aliyun --region ap-southeast-6 ecs DescribeAvailableResource \
  --ZoneId ap-southeast-6a --DestinationResource InstanceType --ResourceType instance \
  --InstanceType ecs.g8i.2xlarge
```

**返回 `{"RequestId":"..."}`（空）** → 该规格在该 AZ 不存在。

指定单规格的两个 AZ 均返回空。改用不带 `--InstanceType` 的全量查询后确认根因：**g8i 整族不在马尼拉商品目录**。

### 3.2 马尼拉实际可售规格（两 AZ 均有库存，`Status=Available/WithStock`）

| 规格族                                       | 6a   | 6b   | 规格档位                                                                                                                    |
| ----------------------------------------- | ---- | ---- | ----------------------------------------------------------------------------------------------------------------------- |
| **`g9i`**                                 | ✅ 12 | ✅ 12 | large / xlarge / 2xlarge / 3xlarge / 4xlarge / 6xlarge / 8xlarge / 12xlarge / 16xlarge / 24xlarge / 32xlarge / 48xlarge |
| `c9i`                                     | ✅ 12 | ✅ 12 | 同上全系                                                                                                                    |
| `r9i`                                     | ✅ 12 | ✅ 12 | 同上全系                                                                                                                    |
| `g9ae`                                    | ✅ 10 | ✅ 10 | 缺 3xlarge / 6xlarge                                                                                                     |
| `c9ae`                                    | ✅ 10 | ✅ 10 | 缺 3xlarge / 6xlarge                                                                                                     |
| **`g8ine`**                               | ✅ 5  | ✅ 5  | large / xlarge / 2xlarge / 4xlarge / 8xlarge                                                                            |
| `c8ine`                                   | ✅ 5  | ✅ 5  | 同上                                                                                                                      |
| `u2a` / `u2i`                             | ✅    | ✅    | 通用算力型（性价比路径）                                                                                                            |
| `e`（经济型）                                  | ✅    | ✅    | 低成本路径                                                                                                                   |
| `t6` / `d2s` / `g5ne` / `g7nex` / `c7nex` | 部分   | 部分   | 老一代，部分售罄                                                                                                                |

**第 8 代中仅 `g8ine` / `c8ine`（网络增强型）在马尼拉，`g8i` / `g8a` / `g8y` / `c8i` / `r8i` 均无。**

### 3.3 售罄清单（8 项，与方案无关）

```
ecs.c7nex.large / .xlarge / .2xlarge
ecs.g5ne.16xlarge / .18xlarge
ecs.g7nex.large / .xlarge / .2xlarge
```

### 3.4 替代建议

| 定位         | 机型                           | 理由                                                                   |
| ---------- | ---------------------------- | -------------------------------------------------------------------- |
| **主力（推荐）** | **`ecs.g9i.2xlarge`**（8C32G） | 与 `g8i.2xlarge` 同核数同内存比（1:4），第 9 代，全档位有货                             |
| **网关优选**   | **`ecs.g8ine.2xlarge`**      | 官方定位即「网络接入层网关、流量转发、预处理中间件」— 与 new-api 网关负载高度契合；`ine` 为网络增强，转发 PPS 更强 |
| 计算密集       | `ecs.c9i.*`                  | 1:2 比例                                                               |
| 内存密集       | `ecs.r9i.*`                  | 1:8 比例                                                               |
| 成本优先       | `ecs.u2i.*` / `e-c1m*`       | 通用算力 / 经济型                                                           |

**节点池配置建议**：`g9i.2xlarge` 为主 + `g8ine.2xlarge` 作备，跨 `6a`/`6b` 双 AZ 混布。

> ⚠️ 库存为**瞬时值**。D1 实际采购前需重跑本项。

## 四、Q3 OSS 同城冗余 ZRS — 支持，但可用性打折

### 4.1 结论（文档级，证据 A）

| 维度          | 结论                                      |
| ----------- | --------------------------------------- |
| 马尼拉是否支持 ZRS | ✅ 支持（ZRS 要求 ≥2 AZ，马尼拉为 2 AZ）            |
| 数据持久性       | **12 个 9** — 与 3 AZ 地域同级                |
| **服务可用性**   | **99.99%** ⚠️ — **不是** 3 AZ 地域的 99.995% |

**ZRS 服务可用性分档：**

| 可用性         | 地域                                                |
| ----------- | ------------------------------------------------- |
| **99.995%** | 杭州、上海、北京、张家口、乌兰察布、深圳、中国香港、东京、**新加坡**、雅加达、吉隆坡、法兰克福 |
| **99.99%**  | 硅谷、弗吉尼亚、**马尼拉**、曼谷、首尔、迪拜、伦敦、柔佛、巴黎                 |

### 4.2 对 SLA 推导的影响

- 产物落 OSS 且纳入 SLA 链 → 新增一项 **0.9999**，`0.9999⁵ ≈ 0.9996`，结论不变
- **风险**：按通用值 99.995% 计算会得虚高乐观值 → **文档须写死 99.99%**
- **优化**：要拿 99.995%，唯一路径是把存储放**新加坡**（3 AZ）

### 4.3 未实测原因

`aliyun` CLI 不含 OSS OpenAPI（`aliyun oss ListBuckets` 报 `not a valid command`）。`GetBucketInfo` 需 `ossutil` 或 SDK 签名调用。本项**产品级 SLA 与具体 Bucket 无关**，故维持文档结论。

如需实测，补 `OSS_BUCKET=<name>` 后重跑脚本，或走控制台 D 级目视。

## 五、Q4 CMS 拨测点 — 实测可用，但原「曼谷清零」结论需修正

### 5.1 实测输出

```bash
aliyun --region ap-southeast-6 cms DescribeSiteMonitorISPCityList
```

**全球拨测点总数：110**。东南亚 5 城明细：

| 国家              | 城市           | ISP         | IPv4 探针 | IPv6 探针 | WinProbe | Browser | 探针 IP                                             |
| --------------- | ------------ | ----------- | ------- | ------- | -------- | ------- | ------------------------------------------------- |
| **Philippines** | **Manila**   | **Alibaba** | **2**   | 2       | 0        | 0       | `8.220.149.213`, `8.212.168.4`                    |
| Singapore       | Singapore    | Alibaba     | 2       | 2       | 0        | 0       | `47.245.104.155`, `47.237.17.19`                  |
| Thailand        | Bangkok      | Alibaba     | 2       | 2       | 0        | 0       | `8.213.210.244`, `8.213.221.47`                   |
| Indonesia       | Jakarta      | Alibaba     | 2       | 2       | 0        | 0       | `8.215.60.204`, `8.215.14.60`                     |
| Malaysia        | Kuala-Lumpur | Alibaba     | 3       | 2       | 0        | 1       | `47.250.83.225`, `47.250.152.91`, `47.254.204.39` |

配额：`SiteMonitorTaskQuota=200`，`SiteMonitorIdcQuota=5`。

### 5.2 关键修正

**「曼谷拨测点已清零」不成立。**

原因是混淆了两套节点池：

| 产品                                 | 节点池                    | 马尼拉                                                                                                          | 曼谷                                                   |
| ---------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| **CMS 站点监控**（SiteMonitor）          | 阿里云自有拨测机房              | ✅ 1 城 1 点（`8.220.149.213` 等）                                                                                 | ✅ 1 城 1 点（`8.213.210.244` 等）                         |
| **云拨测**（ARMS Synthetic Monitoring） | 各运营商 IDC + LastMile 节点 | ⚠️ `Philippines_GlobeTelecom` 已于 2025-03-18 下线，余 `Convergeict` / `Web.ph.Inc` / `Smart` / `Eastern` / `PLDT` | ❌ `Thailand_3BBBroadband` 已于 2025-03-18 下线，此后无 PC 端点 |

→ 用户方案中写的「**CMS 拨测点**」对应 **CMS 站点监控**，**马尼拉与曼谷均有节点**。原判断只对「云拨测」成立。

### 5.3 但仍有两项真实风险

1. **单城单点** — 东南亚每城仅 1 个拨测节点。单点误报会直接触发回滚判定，无交叉验证。
2. **视角失真** — 站点监控探针均为**阿里云机房**（`isp=Alibaba`），测的是「阿里云机房 → 你的 ALB」链路，**不等于菲律宾本地用户体验**（用户走 Globe / PLDT / Convergeict / Smart）。且 `WinProbe=0`、`BrowserProbe=0`，只有 IPv4/IPv6 的 HTTP 探针，**无法做页面级/浏览器级监测**。

### 5.4 建议

| 需求             | 方案                                              |
| -------------- | ----------------------------------------------- |
| 基础可达性 + SLA 证据 | CMS 站点监控，马尼拉 + 曼谷各建任务（可用）                       |
| 多运营商交叉验证       | 云拨测（ARMS）选马尼拉剩余运营商节点（`Convergeict` 不支持 IPv6，注意） |
| 真实用户视角         | 自建探针（菲律宾本地轻量 ECS / 第三方 RUM），或在 App/网页端埋前端 RUM   |
| 浏览器级监测         | 站点监控不支持 → 必须走云拨测 BrowserProbe 或自建 Playwright 探针 |
