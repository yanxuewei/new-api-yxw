# 2026-10-29

## 渠道测试「自动检测」下 VolcEngine Seedream 报 invalid image request type（已修）

- 现象：渠道类型 火山方舟 + 模型 `doubao-seedream-5-0-flash-260915`，测试弹窗保持「自动检测（默认）」时失败，报 `invalid image request type (convert_request_failed)`；直连 `POST https://ark.cn-beijing.volces.com/api/v3/images/generations` 正常。价格已配好，与计费无关。
- 根因：`controller/channel-test.go` 里端点判定与请求体构造是两套逻辑，且不同步。
  - `testChannel()` 的自动检测把 `requestPath` 改成 `/v1/images/generations`（原逻辑 `channel.Type==VolcEngine && Contains(model,"seedream")`）；
  - `GenRelayInfo` 由该路径推出 `RelayMode = RelayModeImagesGenerations`；
  - 但 `buildTestRequest()` 的自动检测分支只有 rerank / embedding / codex / chat，**没有 seedream**，返回的是 `*dto.GeneralOpenAIRequest`；
  - 于是 `switch info.RelayMode` 进 `RelayModeImagesGenerations` 分支，`request.(*dto.ImageRequest)` 断言失败 → `invalid image request type`。
- 修复（`controller/channel-test.go`）：
  - 新增 `isChannelTestImageModel(channel, model)`，路径判定与请求体构造共用同一条件，杜绝再次漂移；
  - 新增 `newImageTestRequest(model, channel)`：VolcEngine Seedream **不发送 OpenAI 专有的 `n`**（Ark 图像接口未文档化该参数，改用 `sequential_image_generation`），其它 provider 仍带 `n=1`；显式选「图像生成」端点与自动检测两条路径都走它；
  - 回归测试 `TestBuildTestRequestVolcengineSeedreamBuildsImageRequest`（`controller/channel_test_request_test.go`），并断言同名模型在非 VolcEngine 渠道仍走 chat。
- 验证：`go build ./...` OK；`go test ./controller/` 全包通过（73s）。
- 临时绕过（未重启前的旧二进制也适用）：测试弹窗把「端点类型」显式选成 **图像生成**，该分支本来就产出 `ImageRequest`，可直接测通。
- 备注：真实业务流量（前端/客户端直接打 `/v1/images/generations`）不受此 bug 影响，只坏在渠道测试的合成请求上。

## 渠道测试测 seedance（视频模型）报 "image generation is only supported by certain models"（已加守卫）

- 现象：端点类型选 `Image Generation` 后批量测 6 个模型，seedream-5-0-flash 通过，`doubao-seedance-2-0-fast-260128` 报 Ark 400 `The parameter 'model' ... is not valid: image generation is only supported by certain models`；`doubao-seedance-2-0-mini-260615` 另报「模型价格未配置」。
- 根因：测试弹窗的端点类型是**整批统一**的；seedance 是**视频模型**，只能走 `/v1/videos` 异步任务（`relay/relay_adaptor.go:147-148` 把渠道 45/54 都映射到 `doubao` 任务插件）。弹窗下拉里没有视频端点（`channel-test-dialog.tsx:175` 只有 8 个同步端点），硬套 images 端点必然被 Ark 拒绝。
- 修复：`controller/channel-test.go` 新增 `isChannelTestVideoModel`（VolcEngine + `seedance`），在端点判定前直接返回本地错误，文案指向 `/v1/videos`，不再发上游请求、不再显示误导性 400。回归测试 `TestChannelTestRejectsVideoGenerationModels`；`go test ./controller/` 全包通过。
- 为什么不做「让测试通过」：`/v1/videos` 是异步任务（提交→轮询→建 task 记录→计费），塞进同步测试按钮等于偷偷造付费任务，风险大于收益。
- seedance 正确验证：`POST /v1/videos`（body 需 `model`/`prompt`/`seconds`，有图则 `image` 或 `input_reference` → image_to_video）→ `GET /v1/videos/{task_id}` 轮询；前提是任务插件 `doubao` 已启用且渠道已绑定。

## seedance 在 new-api 的可用性核查（结论：出厂可用，不必绑插件）

- 插件是**内嵌**的（`plugins/embed.go:12 //go:embed tasks`），registry 默认 `masterEnabled=true`，只有显式 disabledFactory 才关；`plugins/tasks/doubao/plugin.js:255` 声明 `channelTypes: [54, 45]`，火山方舟渠道原生命中。
- **绑定不是必需**：`middleware/distributor.go:169-183` 只在渠道类型 61（任务插件）/ NewAPI 时校验 `task_plugin_key`；45 走 `channelTypes` 匹配。渠道测试里 `ChannelTypeDoubaoVideo(54)` 被 unsupported 列表拦，但 45 不拦 —— 所以 45 + seedance 会进到测试逻辑（这也是本轮加守卫的原因）。
- 视频调用契约（`plugin.js:739 buildSubmitRequest`）：`prompt`→content text、`images[]`→image_url、`seconds`→`duration`、`metadata` 原样并入 Ark body；响应 `{id, object:"video", status: queued|in_progress|completed|failed}`，轮询 `GET /v1/videos/{id}`，取视频 `GET /v1/videos/{id}/content`。
- ⚠ 潜在坑：`doubao-seedream-5-0-flash-260915` **不在** `plugin.js` 的 `IMAGE_MODELS` 里 → 走 `/v1/images/generations` 无影响（不经过插件），但若用 `/v1/responses` 带 image 工具走它，`imageTask()` 判不出来会被当视频任务。补 profile 需先确认官方 preset/像素上下限。
