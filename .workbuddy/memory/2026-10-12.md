## ★ `.hk` 能否用 DV 证书 —— 定论：**可以**（用户提问核查，2026-10-12）

### 用户疑问
控制台购买页提示「DV 证书无法为特殊域名/公网IP签发证书（例如：.edu、.gov、.org、.jp（国家缩写）等后缀域名）」，用户据此怀疑 `.hk`（同为"国家缩写"）也不能用 DV。

### ★ 定论：`.hk` 不在任何受限清单内，DV 通配符可用
**该提示列的是「枚举清单」，不是「所有国家缩写后缀」** —— 清单里只有 `.jp` 一个 ccTLD。

| 证据源 | 受限后缀清单 | 含 `.hk`？ |
|---|---|---|
| 阿里云国际站《Issue Certificates》 | DigiCert 品牌不支持 `.edu .gov .org .jp .pay .bank .live .nuclear .ru`；**GlobalSign 品牌无此限制** | ❌ |
| 阿里云中国站《申请证书》/《创建SSL证书》 | 同上（个人测试证书同清单） | ❌ |
| 腾讯云《免费 SSL 证书概述》 | `.edu .gov .org .ru .jp .pay .bank .live .nuclear` —— **与阿里云逐字相同** | ❌ |
| CA 侧制裁黑名单（tbs-certificate 汇总） | DigiCert: `.by .cu .ir .kp .sy .ru .su .ua .ve`；GlobalSign: `.ru .cu .ir .kp .sd .sy`；Sectigo: `.ru .by .ir .kp .cu .af .sy …` | ❌ |

**受限的真实成因（不是"因为是国家缩写"）**：
1. **注册资格本身有身份门槛** ⇒ DV 的"仅验证域名控制权"不足，CA 强制升 OV：`.jp`（JPRS 要求注册人须与日本有联系）、`.edu` / `.gov`（注册资格限定特定机构）
2. **国际制裁 / CA 合规黑名单**：`.ru` `.ir` `.kp` `.sy` 等
3. **高危词风控**：`.pay` `.bank` `.live` `.nuclear`
⇒ `.hk`（中国香港，HKDNR 管理，**对全球开放注册、个人/企业均可注册、无身份门槛**）三条都不命中。

**旁证**：① 阿里云控制台「输入域名购买」会**自动匹配该域名支持的证书类型/品牌**（文档明示），截图里 DV 仍为可选态；② 主流 DV-only CA（Let's Encrypt）对 `.hk` 无后缀限制。

**残留不确定性（诚实标注）**：官方清单末尾带「等」字，且 CA 黑名单可随时调整 ≠ 永久承诺。**最终判定权在下单那一刻 CA 的域名资格校验**；若不合格会返回明确报错。GlobalSign 品牌可完全规避 DigiCert 的该清单。

### 侦查：「能否在 443 上做 www.likha.hk 跳转」（2026-10-12 15:1x · 只读，未改任何资源）

**结论：技术可行**（443 已有通配符证书、Redirect 注解对 HTTPS 监听同样有效），但**方案取决于「跳到哪」**，且有三个硬前提。

- **mnl ALB 规则现状**（`lsn-ihrgkty2sjdy8s5p4h`:80 / `lsn-hjl2cz2g9oqvee4eix`:443）：
  - `:80` = `rule-80-1` www→301 · `rule-80-2` likha.hk→301 · `rule-80-3/4` internal→canary · `rule-80-5` Path=/* → stable（nohost 兜底）· `rule-80-6` Path=/* → FixedResponse 404
  - `:443` = `rule-443-1` internal→stable · **`rule-443-2` Path=/* → stable（nohost 兜底）** ⇒ **`www.likha.hk`/`likha.hk` 在 443 上无显式规则，全走兜底命中**
- **mnl Ingress 全景（order / listen-ports）**：`new-api-http-redirect` order **1** `[{"HTTP":80}]` · `new-api-canary-weight` 45 · `new-api-canary-header` 46 · `new-api-stable-ip` order **50** `[{"HTTP":80},{"HTTPS":443}]`（**443 兜底来源**，nohost→stable） · `new-api-catchall-404` order **100** **未设 listen-ports ⇒ 只在 80**（⇒ **443 上无 404 兜底**）。
- **三个硬前提**：① 443 要覆盖兜底，新规则 order **必须 < 50**（`rule-443-2` 来自 order=50 的 `new-api-stable-ip`）② **不要往 `new-api-http-redirect` 上加 443**（它含 `likha.hk`，会连根域一起跳 ⇒ 循环）⇒ 若要 443 跳转应**新建独立 Ingress** ③ 证书已由 AlbConfig 443 listener 提供（通配符 `*.likha.hk` 覆盖 www，所有 Ingress 的 `certificate-id` 注解均为空），无需新增。

- ⚠️ 另注意：443 无 404 兜底 ⇒ 伪造 Host 走 `rule-443-2` 仍 **200**（任务 47 未办）。

## 裸 IP 直访「白屏」诊断（16:13–16:35 HKT · 只读，未做变更）

- **现象**：用户报告 `http://8.212.161.49` 白屏（此前可用）。
- **服务端无故障**：`http://8.212.161.49/` → 200 + 完整 SPA HTML（1047 B）；`/api/status` → 200；静态资源可达；**无 HSTS / 无 Location**；带浏览器 UA 请求结果一致。
- **★ 根因**：浏览器把裸 IP 升级到 HTTPS ⇒ ALB 443 默认证书 `CN=*.likha.hk`（SAN 不含 IP）⇒ 证书校验失败。
  - 浏览器对 IP 字面量**不发 SNI**（RFC 6066）⇒ ALB 回落 443 监听默认证书；SAN 不匹配 ⇒ 拒绝。
  - **★ 忽略证书后仍白屏**（关键）：主 HTML 能加载，但 `/static/js/*` 逐个子资源同样校验失败 ⇒ React 不渲染 ⇒ `#root` 空。
- **★ Chrome headless 复现**（`--dump-dom` 后统计 `#root` 内容长度）：`http://IP` = **49880** ✅ / `https://IP` = **0（DOM 都拿不到）** ❌ / `https://IP --ignore-certificate-errors` = HTML 1053 B 但 **`#root`=0（白屏）** ❌ / `https://www.likha.hk` = **49880** ✅。**http 与 https-www 完全一致** ⇒ 页面无 IP/域名差异化逻辑，唯一变量是证书。
- **★ 为什么是"今天"**：443 是今天（任务 19/25 闭环）才上线的。**上线前** https 握手被拒 ⇒ 浏览器**回退 http** ⇒ 正常；**上线后**握手成功但证书错 ⇒ **不回退**（证书错误 ≠ 连接不可达）⇒ 白屏。
- **结论**：公网裸 IP 的 HTTPS **无解**（CAS DV 不签 IP SAN；IP 证书需 OV + IP 所有权而 ALB IP 是共享资产；自签名浏览器不信任；ALB 的 HTTPS 监听必须有默认证书、不支持"拒绝未知 SNI"；关 443 会废掉域名业务）⇒ **修正 10-06 裁定 A 的边界：裸 IP 直访仅限 HTTP**，对外统一 `https://www.likha.hk`。

## ★ Ingress ↔ ALB 规则对账（2026-10-12 16:43–17:05 · 用户提问「new-api-stable-ip 似乎没和 rule-443-2 对应？」）

- **★ 对账模型（本次确立）**：**1 个 Ingress → N 条 ALB 规则**，`N = (host×path 组合数) × listen-ports 数`。控制台「路由」页按 **Ingress 聚合**显示、「转发规则」页按 **规则平铺且不带 Ingress 归属** ⇒ **非 1:1**，这就是"看着对不上"的唯一原因。
- **★ 四组实测展开（原始 ID 级）**：
  - **mnl 443 = 3**：`rule-443-1` Host=`likha.hk` **Redirect 308**（← `https-canonical`）· `rule-443-2` Host=`ph-verify…` → `sgp-j4qrgy3f7bcv1r67na`（← `stable-ip` p1）· `rule-443-3` Path=`/*` 无 Host → 同组（← `stable-ip` p2）。
  - **mnl 80 = 6**：`rule-80-1/2` www+根域 **301**（← `http-redirect`）· `rule-80-3` Host=`ph-verify`+**Header** → `sgp-slwubl6v6sb2xtsxrz` canary w100（← `canary-header`）· `rule-80-4` Host=`ph-verify` → **canary `sgp-1eevkvsn0c32t3e1ya` w5 + stable `sgp-j4qrgy3f7bcv1r67na` w95**（← `canary-weight`，**含合并**）· `rule-80-5` 无 Host → stable（← `stable-ip`）· `rule-80-6` **FixedResponse 404**（← `catchall-404`）。
