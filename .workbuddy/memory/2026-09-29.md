## 任务 11 机型复核：`ecs.c9i.2xlarge` 能否替代 `ecs.g9i.2xlarge`？

**结论：技术上可选（双区有货），工程上不可选。基线维持 `ecs.g9i.2xlarge`。**

### 实测数据（ap-southeast-6，`aliyun ecs`）

| 机型 | 规格族 | vCPU | 内存 | 小时价(含40G ESSD) | 双区可用 |
|---|---|---|---|---|---|
| `ecs.g9i.2xlarge` | 通用型 g9i | 8 | **32 GiB** | $0.379328 | ✅ 6a/6b `Available/WithStock` |
| `ecs.c9i.2xlarge` | **计算型 c9i** | 8 | **16 GiB** | $0.311728（-17.8%） | ✅ 6a/6b `Available/WithStock` |
| `ecs.g9ae.2xlarge` | 通用型 g9ae（AMD） | 8 | 32 GiB | $0.427328（+12.7%） | ✅ 6a/6b |
| `ecs.g8ine.2xlarge` | 通用型 g8ine | 8 | 32 GiB | $0.471828（+24.4%） | ✅ 6a/6b |

- 内存单位交叉验证：`g9i.4xlarge` 回显 16C/**64** → `MemorySize` 单位为 **GiB**（非文档惯例的 MiB）。
- 配额：`q_ecs_enterprise_postpay_c` Total=64 / Usage=0（未消耗）。

### 否决理由（按权重）

1. **配额是 vCPU 硬墙，不随内存比变化**：64 vCPU ÷ 8 = 最多 8 台 → g9i 总内存 256 GiB，c9i 仅 128 GiB，**容量腰斩**。
2. **违反坑 9**「`instance_types` 只混同规格族」：c9i(8C16G) 与 g9i(8C32G) 内存比不同，混用使 `request/limit`（2C4G/4C8G）与 HPA 口径错乱。
3. **4 节点常态触线**：c9i 4×16 = 64 GiB = HPA 满配请求（16 副本 × 4Gi），扣 ACK 托管组件 + kubelet/OS 预留后必 Pending —— 即坑 1「HPA 达标假象」。
4. 若要整体换 c9i：须全量统一 + 重算 `ResourceQuota`（现 `requests.memory 96Gi`/`limits.memory 128Gi`）+ HPA max + §2.1 + §14 成本表，且 vCPU 配额 100% 吃满、autoscaler 无余量。

### 顺带修正的一处认知

- 文档原写「同批在售备选：`g8ine.2xlarge`、`g9ae.*`、`c9i.*`」——**把 c9i 与同内存比机型并列会误导**。已就地改为分级说明：g8ine/g9ae 可入 `instance_types`；c9i 单独加 ⛔ 否决块（含三重理由）。

### 价格副产物（马尼拉 8C32G 档）

- g9i 已是该档**最便宜**的（g9ae +12.7%、g8ine +24.4%）→ 无更优替代，省钱只能走压测后调 HPA max 或包年包月，不能靠换族。
- 4 节点月成本：g9i **$1,107.64** vs c9i $910.25（差 $197.39/月）。

## 购买页选项复核：eRDMA 驱动 与 云盘容量口径（fanyan 问）

### ① eRDMA 驱动 —— 好处明确，但本项目不勾

**支持性实测**（`ecs DescribeInstanceTypes` 的 `EriQuantity`，>0 = 支持 eRDMA）：

| 机型 | EriQuantity |
|---|---|
| `ecs.g9i.2xlarge` | **1** ✅ |
| `ecs.c9i.2xlarge` | **1** ✅ |
| `ecs.g9ae.2xlarge` | **2** ✅ |
| `ecs.g8ine.2xlarge` | **0** ❌ 不支持 |

- 收益（零拷贝 / 内核旁路 / 协议卸载 → 8μs 级时延、双向 200Gbps、CPU 占用低）**只对 RDMA verbs 应用生效**：NCCL / MPI / RDMA-aware 缓存，或经 NetACC / SMC-R 显式适配。new-api 是 HTTP/TLS 网关 → **勾驱动也不生效**。
- 代价：多一个内核模块（随节点 OS 镜像升级需反复维护）、建节点 +3~5 min、还需**额外挂 ERI 弹性 RDMA 网卡**（ACK 托管节点池不管理 ERI 生命周期）。
- **官方关键一句：eRDMA 跨可用区时时延大幅上升、与普通 VPC 基本一致** → 节点池 `multi_az_policy=BALANCE` 本就跨区分布，天然吃不到收益。
- 节点池路径不经过 ECS 购买页：ACK 节点镜像由 `image_type` 决定，购买页 cloud-init 与节点池 `user_data` 是两套。

- 阿里云口径（创建按量付费云盘文档原文）：**总容量 = 云盘容量 × 购买量**。→ 页面底部「各类型云盘容量购买情况」= **整单合计**；上方表单 = **单实例配置**。

## 公网 IP 与安全组复核（fanyan 问「已有 EIP 还要分配公网 IPv4 吗？要新建安全组吗？」）

**结论：① 不勾「分配公网 IPv4」；② 要建安全组，但必须是普通安全组，且不在购买页建。**

### ① EIP 与 ECS 公网 IP 是两条独立通道

实测 `DescribeEipAddresses`：8 个 EIP **全部 `InstanceType=Nat`**，`InstanceId` 指向 `ngw-5tss1ii326puzw4tdwy70`（马尼拉 4 个）/ `ngw-t4n7gdnoh56rwrw3zds48`（新加坡 4 个），状态全 `InUse`。

| 通道 | 载体 | 作用 | 现状 |
|---|---|---|---|
| 出公网 | 8 EIP + NAT 网关 + SNAT | VPC 内实例共享出口 IP | ✅ 已建且占用 |
| 入公网 | 「分配公网 IPv4」或另绑 EIP | 外部可主动访问该实例 | ❌ 不配 |

- **一个 EIP 同时只能绑一个实例** → 这 8 个不能转给 ECS 用。
- 节点入站走 ALB（`sg-mnl-app` 只放行 `sg-mnl-alb` 打 3000），出站走 NAT → **不需要公网 IP**；自持公网 IP 只会扩大攻击面。
- 「分配公网 IPv4」= **固定公网 IP、随实例生命周期、不可解绑**；EIP 可解绑/换绑/回收 → 真需要公网时优先 EIP。
- API 侧对应：节点池 `scaling_group.internet_max_bandwidth_out = 0`（body 已设 0）。

### ② 安全组：必须普通安全组

- **企业级安全组不支持「组组授权」**（官方原文：*不能把安全组 ID 作为授权对象，也不能被其他安全组规则引用*）→ §8.1 规则表 5 条组引用全废。附带差异：企业级默认**组内隔离且不可改**；容量 65536 vs 普通 6000 私网 IP；普通组组授权规则**上限 20 条**。
- **ECS 购买页「新建安全组」默认模板不能用**：命名成「默认安全组」，且自带 RDP 3389（Ubuntu 用不上，纯攻击面）+ SSH 22 对 `0.0.0.0/0`（控制台自己都在警告）。

### ★ 实跑踩到的 4 个坑（v1 脚本三处缺陷，值钱）

1. **入向 / 出向是两个 API**：`AuthorizeSecurityGroup` **只加持入向规则**，用它建出向**返回 RequestId 却一条不落**（6 条出向全丢）。出向必须 `AuthorizeSecurityGroupEgress`（该 API 另有 `Permissions.N.DestGroupId`）。→ **推翻了我上一轮"组引用只支持入向"的结论。**
2. **错误检测不能只认 JSON `"Code"`**：aliyun CLI 失败输出是 `ERROR: SDK.ServerError` + **文本行 `ErrorCode: xxx`**（非 JSON）→ v1 把失败当成功报「已添加」。
3. **`2>/dev/null` 吞异常 → 重复建组**：查询报错被当"不存在"→ VPC 里出现两个 `sg-mnl-app`（多建的 `sg-5tsaatp5w68vyeysqnol` 已撤销引用 + 删除）。改为「查不到=报错退出」，绝不猜。
4. **`IFS=$'\t' read` 拆 TSV 不可用**：tab 属 IFS 空白字符 → 连续 tab（空字段）被折叠 → 列错位（key 全错，幂等判断失效）。改为让 jq 直接 `join("|")` 拼整条 key。

补充实测：`Permissions.N.*` 路径下**重复规则不报 `InvalidPermission.Duplicate`**，而是静默去重 → 区分「新增/已存在」只能前置比对。另 `--SecurityGroupName` 过滤改精确 JMESPath `[?SecurityGroupName=='x']`（不再依赖 `[0]`）。
