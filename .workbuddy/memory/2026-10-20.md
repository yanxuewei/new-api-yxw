## 09:46–10:05 · JKT dev：补齐 new-api-pre / new-api-perf 的 slave 节点

**背景**：JKT dev 集群 `newapi-dev` 里每个环境都是 master + slave 双 Deployment（如 `new-api-dev` / `new-api-dev-slave`、`yxw-new-api-master` / `yxw-new-api-slave`），而 `new-api-pre` / `new-api-perf` 只有 master。fanyan 要求参照 dev 补 slave。

### 代码层语义核实（决定 template 差异的依据）
- `common/init.go:89`：`IsMasterNode = os.Getenv("NODE_TYPE") != "slave"` ⇒ 非 "slave" 即主。
- `model/main.go:215`（主库）与 `:262`（日志库）：`if !common.IsMasterNode { return nil }` ⇒ **slave 跳过全部 DB migration**。
- 同样被 slave 跳过的后台任务：`service/system_task.go:125`、`service/subscription_reset_task.go:31`、`service/auth_cleanup.go:16`、`service/codex_credential_refresh_task.go:37`、`service/authz/enforcer.go:57`。

### master / slave 的模板差异（照 `new-api-dev-slave` 落地）
| 项 | master | slave |
|---|---|---|
| `NODE_TYPE` | master | **slave** |

### 关键设计决策：slave 用独立 app 标签

### 顺带查清的接口事实（已写进 README 备查）
