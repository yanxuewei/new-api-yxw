## nodePort 固化 32656（11:44–11:52，用户批准）

**用户问**：链路图里 `svc newapi-np 80:32656` 的 32656 是什么？（→ 答：k8s NodePort Service 三段映射 `port:nodePort`，80 = ClusterIP 端口〔集群内〕，**32656 = 每个节点主机端口**，ALB 服务器组 Ecs 型挂的就是 `节点IP:32656`；再往下 `targetPort=3000` = 容器端口。80 只在集群内有效，节点外连不上。）→ 用户：**「可以固定下来」**。

1. `kubectl patch svc newapi-np` 显式补 `nodePort: 32656` + `externalTrafficPolicy: Cluster` → 回 `patched (no change)`（同值 no-op，零风险）；

## 澄清：证书 ≠ 后端类型（ENI 型 80 明文完全可用）（11:58–12:10）

**用户问**：「证书到位后走 `sgp-tqgwt413t19mum8oa9`。没有证书，就只能走 NodePort=32656 转发？不能走 ENI/Pod IP 型？为什么，需详细说明区别和最佳应用场景。」

**核心纠正：前提不成立。** 证书只决定**能否开 443**，与服务器组类型**毫无关系**；ENI 型在 80 明文下**完全可用**。当时选 NodePort 是**工程绕路**，不是 ALB 能力限制。

**真正挡住的了两件事（本轮实测取证）**：
1. **Ingress `new-api-verify` 把 `host` 写死** `ph-verify.internal.likha.hk` ⇒ Controller 只生成一条规则 `rule-80-1`（Host+Path `/*`）→ ENI 组。IP 直访 `Host:` = IP，**不匹配** → 落 `DefaultActions` ⇒ **ENI 组压根没机会被命中**。
2. **`AlbConfig mnl-alb` 声明** `listeners[0]: 80 → httpDefaultActions=[Redirect {host: www.likha.hk, https: true, port: "443"}]`。若把 ENI 组设成 default，会被 reconcile 打回；且 `likha.hk` NS NXDOMAIN，跳转本身就是死路。

**本轮新实测数据**：
| 项 | `sgp-tqgwt413t19mum8oa9` | `sgp-fm7kdwz99wtzbffkfx` |
|---|---|---|
| ServerGroupType | `Instance` | `Instance` |
| 后端 ServerType | **`Eni` ×4** | **`Ecs` ×4** |
| 后端端口 | **3000** | **32656** |
| HealthCheckEnabled | `true`（GET /api/status, 6s/3s, 2xx） | **`false`** |
| ConnectionDrain | `true, 120s` | `false`（300s） |

| ServiceName | `new-api-new-api-stable-80` | `kube-system-fake-svc-80` |

⇒ **两组其实都是 Controller 托管的**（`sgp-fm7kdwz99wtzbffkfx` 也有 `albconfig=kube-system/mnl-alb` tag、`ingress_name=mnl-alb-listener-80`，是 AlbConfig 监听器默认动作对应的组）—— 修正此前"手工建的组"的表述。

**★ 重要误解纠正**：ALB 是**七层**。HTTP/HTTPS 监听下，**两型后端的客户端真实 IP 都来自 `X-Forwarded-For`**（`xForwardedForConfig.XForwardedForEnabled` 默认开启且**不可关闭**）。**不存在「ENI 才有真实源 IP」** —— 那是四层 CLB/NLB 语境。选型时别拿"源 IP"当 ENI 优势。

**ENI vs ECS/NodePort 差异要点**：ENI = 一跳直连 / Controller watch EndpointSlice 自动增删 / 健康检查必须开（Pod IP 会回收复用）/ ConnectionDrain 120s / Controller 独家管（手工改被覆盖）/ 需 Terway ENI 模式。ECS = 经节点二次转发（跨节点需 SG）/ 后端与 Pod 生命周期解耦 / 健康检查可关 / 手工可控 / 任意 CNI。

**最佳场景**：ENI = 生产主路径（域名+Ingress+HPA）；ECS/NodePort = 兜底/应急/Controller 不可用/混合后端/网络诊断；**混合分流** = Host 规则走 ENI、default 走 NodePort（**ALB 规则优先于 default**，故并存 = 当前架构）。

**想让 IP 直连走 ENI 的正确做法**：新增**不带 `spec.rules[].host` 的 Ingress** ⇒ 生成**无 Host 条件的 Path-only 规则**（优先级在 Host 规则后、default 前）⇒ IP 直访命中 ENI 组，且**不受 default action 被 reconcile 改回 Redirect 的影响**；副作用 = 该规则会吃掉所有未被 Host 规则命中的流量。**不推荐**直接把 ENI 组设成 default。

**产物**：`deploy/ALB后端类型选型_Eni-vs-NodePort型.md`（完整对比 + 场景 + 方案）；探针 `deploy/task_alb_url_bodies/27-albconfig-inspect.sh`。

### 23:10｜HPA 扩缩容策略文档 + 两处实况发现

**产出**：`deploy/HPA扩缩容策略详解_hpa-new-api-stable.md`（原理 + 集群实况 + 诊断命令 + 调参速查）。取数脚本 `deploy/hpa_bodies/{00-get-hpa,01-node-capacity}.sh`。

**实况**：`minReplicas=4` / `maxReplicas=13` / `metrics` **仅 cpu** `averageUtilization=70`；`requests.cpu=2`、`limits.cpu=4`、memory 4Gi/8Gi；当前 `currentReplicas=4` `desiredReplicas=4`，CPU `0%/70%`（`averageValue=1m`）；条件 `ScalingLimited/TooFewReplicas`（想缩但被 min 拦住）。节点 4 × **`ecs.g9ae.2xlarge`**（8 vCPU/32 GiB，allocatable **7910m / 29.5Gi**）⇒ 集群总 allocatable **31.64 核**。

**★ 发现 1（drift）**：live `averageUtilization=70`，但 `last-applied-configuration` 注解里是 **65** ⇒ **有人绕过 apply 直接改了 HPA**。风险：下次任何人 `kubectl apply -f` 旧 manifest 会**静默改回 65**。**待用户裁定 70 是否有意**，是则回写源 manifest 对齐。

**★ 发现 2（容量硬约束）**：`maxReplicas=13` **装不下**。算账：总 allocatable 31.64 核 − 非 stable 占用 6.91 核 = **24.73 核** ÷ 2 核/Pod = **最多 12 个** ⇒ 第 13 个必 `Insufficient cpu` **Pending**。内存不是瓶颈（13×4Gi=52Gi < 118Gi）。三解法：① max→12 ② 全节点池 cluster-autoscaler（需确认是否已启用）③ `requests.cpu` 2→1.5（⚠ 同时把阈值线从 1.4 核降到 1.05 核，HPA 变敏感）。

**★ 阈值口径（本集群实算）**：单 Pod 阈值线 = 70% × 2 核 = **1.4 核**；叠加 tolerance 0.1 死区 ⇒ **低于 63%（1.26 核/Pod）才触发缩容**。该死区**不在 YAML 里**，来自 `--horizontal-pod-autoscaler-tolerance` 默认值。
