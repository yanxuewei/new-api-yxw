## 系统盘 40G → 100G（jkt dev，已执行完成）

- **做法：原地在线扩容，未重建节点、未重启实例、Pod 零重启**（实例 id 与创建时间不变）。
  1. `aliyun ecs ResizeDisk --DiskId d-k1afs8wedv35raib1wif --NewSize 100 --Type online`（+ `d-k1aipvl98ymce2dtlndk`）—— **cloud_essd（PL1）系统盘支持 `--Type online`**，无需停机。ResizeDisk **无 DryRun 参数**（无法干跑），改为「先单台做完验证再第二台」。
  2. 盘内扩分区/文件系统：`deploy/ops/bodies/grow_root_fs.sh`（`growpart /dev/nvme0n1 3` → **根是 ext4 用 `resize2fs`**，不是 xfs；脚本按 fstype 分支）。`growpart` 节点上已有，无需装 cloud-utils-growpart。
  3. 节点池同步：`aliyun cs PUT /clusters/<cid>/nodepools/<npid> --body '{"scaling_group":{"system_disk_size":100}}'`（**body 可只带这一个字段，其余保持**）⇒ 回读 `system_disk_size=100`，ESS 启动配置 `asc-k1ahcn6v6rivopmjugy6` 的 `SystemDiskSize` 也是 100 ⇒ **后续新节点自动 100G**，不回退。
- **结果**：两节点 `/` 均 99G（used 25G/22G，avail 70G/72G，26%/24%）；节点 Ready、DiskPressure=False、无 Pending、无重启。
- **成本**：ESSD PL1 线性计价（脚本口径 `DISK100_H=0.02532 USD/h` ⇒ $0.0002532/GiB/h，H=730）⇒ 每台 +60G = **+$11.09/月**，两台 **+$22.18/月**（年化 ≈$266）。**云盘只能扩不能缩**，此增量不可回退（除非换盘重建）。
- **副产物**：PL1 IOPS/吞吐随容量提升（40G 触底 2120 IOPS / 20MB/s ⇒ 100G 为 5000 IOPS / 50MB/s），对镜像拉取与 containerd 落盘有实际收益。
- 脚本：`deploy/logs/jkt_np_disk100.sh`（改节点池+回读+核对存量实例未被重建）、`deploy/ops/bodies/grow_root_fs.sh`（幂等，NOCHANGE 即已扩）、`deploy/logs/jkt_after_disk_expand.sh`（扩后健康复核）。
- 坑：`aliyun` 在 `wsl bash -c` 里若不先把 `/usr/local/bin` 放进 PATH 前置，会被 Git Bash 做路径转换报 `No such file or directory`；且 PATH 里含空格会刷一串 `export: ... not a valid identifier`（无害，过滤即可）。

- **正确字段**：`kubernetes_config.user_data`，且**值必须是 base64**。
